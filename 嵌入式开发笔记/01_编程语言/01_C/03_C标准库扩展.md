

# ptrdiff_t 

`ptrdiff_t` 是 C 语言标准库 `<stddef.h>` 中定义的一个有符号整数类型。它的主要作用是用来存储两个指针相减的结果，表示它们之间元素的个数或内存地址的差值。`ptrdiff_t` 保证能够容纳同一数组内任意两个指针的差值。它的大小通常与系统的指针大小一致（在 32 位系统上通常是 4 字节，在 64 位系统上通常是 8 字节），确保在任何架构上都能正确表示指针的差。

- **类型**
  有符号整数类型。
- **用途**
  存储两个指针相减的结果。
- **头文件**
  `<stddef.h>`。 

使用 `ptrdiff_t` 时，初学者或经验不足的开发者可能会遇到以下常见问题，这是最常见的错误。当处理大型数组或在 64 位系统上进行指针运算时，如果使用比 `ptrdiff_t` 小的类型（如 `int`），可能会导致整数溢出，从而产生错误的结果。

```c
#include <stdio.h>

void bad_example() {
    long long arr[1000000]; // 假设这是一个非常大的数组
    long long *ptr1 = &arr[900000];
    long long *ptr2 = &arr[100000];

    // 在 64 位系统上，如果差值太大，int 可能会溢出
    // 即使不溢出，在跨平台时也可能不安全
    int diff = ptr1 - ptr2;

    printf("错误差值 (int): %d\n", diff);
}
```

应始终使用 `ptrdiff_t` 来存储指针相减的结果。 

```c
#include <stdio.h>
#include <stddef.h> // 必须包含此头文件

void good_example() {
    long long arr[1000000];
    long long *ptr1 = &arr[900000];
    long long *ptr2 = &arr[100000];

    // 使用 ptrdiff_t 保证安全和正确性
    ptrdiff_t diff = ptr1 - ptr2;

    // 注意：打印 ptrdiff_t 通常使用 %td 格式说明符 (C99 或更高版本)
    printf("正确差值 (ptrdiff_t): %td\n", diff);
}
```

C 语言标准规定，只有当两个指针都指向同一个数组对象的元素，或者指向数组最后一个元素之后的一个位置时，它们相减的操作才是明确定义的。对不相关的指针进行相减，其行为是未定义的，结果不可预测。 

```c
#include <stdio.h>
#include <stdlib.h>

void undefined_behavior_example() {
    int a = 10;
    int b = 20;

    int *pA = &a;
    int *pB = &b;

    // pA 和 pB 指向不同的内存位置，不是同一数组的元素
    // 这是一个未定义行为！
    ptrdiff_t diff = pA - pB;

    printf("未定义行为的差值 (可能的结果): %td\n", diff);
    // 结果可能是任何值，不具有任何逻辑意义。
}
```

如上所述，`ptrdiff_t` 是一个标准类型，在 `printf` 家族函数中，应该使用特定的长度修饰符来确保正确打印。C99 及更高版本
使用 `%td`。 而在旧版本/通用方法有时会转换为 `long` 或 `long long` 使用 `%ld` 或 `%lld`，但不推荐，因为这依赖于 `ptrdiff_t` 的实际大小，可能在不同系统上出错。最佳实践是使用 `%td`。

虽然 `ptrdiff_t` 是处理指针差值的标准和推荐类型，但在某些特定场景下，可能会看到或需要使用其他类型，size_t` 是一个无符号整数类型，用于表示对象的大小（如 `sizeof` 的结果）或计数。如果确定指针差值不会是负数（例如，总是将较小的地址减去较大的地址，或者只需要知道绝对距离），可以使用 `size_t`，但需要先进行一次类型转换或者使用标准函数来获取绝对值。

```c
#include <stdio.h>
#include <stddef.h>
#include <stdlib.h> // 需要 abs 或 labs/llabs

void size_t_alternative() {
    int arr[] = {1, 2, 3, 4, 5};
    int *ptr_a = &arr[0];
    int *ptr_b = &arr[4];

    // 1. 获取有符号差值
    ptrdiff_t diff_signed = ptr_b - ptr_a; // 结果为 4

    // 2. 将其转换为 size_t
    // 如果确定 ptr_b >= ptr_a，可以直接 (size_t)(ptr_b - ptr_a);
    // 否则，使用绝对值函数
    size_t diff_unsigned = (size_t)labs(diff_signed); // labs 用于 long 的绝对值

    printf("有符号差值 (ptrdiff_t): %td\n", diff_signed);
    printf("无符号绝对差值 (size_t): %zu\n", diff_unsigned);
}
```

在极少数情况下（例如，需要跨越不同类型指针的边界进行字节级别操作），可能需要计算指针的字节差，而不是元素差。这通常涉及将指针转换为 `char*` 或 `unsigned char*`，因为 `char` 类型保证长度为 1 字节。 

```c
#include <stdio.h>
#include <stddef.h>

void byte_diff_alternative() {
    int arr[] = {1, 2, 3, 4, 5};
    int *ptr_a = &arr[0];
    int *ptr_b = &arr[1];

    // 将指针转换为 char* 后相减，得到字节差
    ptrdiff_t byte_diff = (char*)ptr_b - (char*)ptr_a;

    // 一个 int 通常是 4 字节
    printf("元素差: %td\n", ptr_b - ptr_a);       // 1
    printf("字节差: %td\n", byte_diff);           // 4 (假设 sizeof(int) == 4)
}
```

总而言之，对于两个同类型指针相减，`ptrdiff_t` 就是最安全、最标准的工具！使用它，能让代码更健壮、更容易跨平台。

# 彩色字体输出

## 1.介绍

在调试程序时，有时候要输出大量数据，如果让`printf/fprintf`改变输出数据的颜色，那观察数据就方便多了。终端的字符颜色是用[转义](https://so.csdn.net/so/search?q=转义&spm=1001.2101.3001.7020)序列控制的，是文本模式下的系统显示功能，和具体的语言无关。转义序列是以` ESC` 开头,可以用` /033 `完成相同的工作（`ESC `的 ASCII 码用十[进制](https://so.csdn.net/so/search?q=进制&spm=1001.2101.3001.7020)表示就是 27， = 用八进制表示的 33）。

##  2.语法格式

```c
"/033[显示方式;前景色;背景色m"
转义序列以'['开头,'m'结尾
//显示方式:0（默认值）、1（高亮）、22（非粗体）、4（下划线）、24（非下划线）、5（闪烁）、25（非闪烁）、7（反显）、27（非反显）
//前景色:30（黑色）、31（红色）、32（绿色）、 33（黄色）、34（蓝色）、35（洋红）、36（青色）、37（白色）
//背景色:40（黑色）、41（红色）、42（绿色）、 43（黄色）、44（蓝色）、45（洋红）、46（青色）、47（白色）
```

## 3.示例代码

```c
#include <stdio.h>

#define NONE         "\033[m"
#define RED          "\033[0;32;31m"
#define LIGHT_RED    "\033[1;31m"
#define GREEN        "\033[0;32;32m"
#define LIGHT_GREEN  "\033[1;32m"
#define BLUE         "\033[0;32;34m"
#define LIGHT_BLUE   "\033[1;34m"
#define DARK_GRAY    "\033[1;30m"
#define CYAN         "\033[0;36m"
#define LIGHT_CYAN   "\033[1;36m"
#define PURPLE       "\033[0;35m"
#define LIGHT_PURPLE "\033[1;35m"
#define BROWN        "\033[0;33m"
#define YELLOW       "\033[1;33m"
#define LIGHT_GRAY   "\033[0;37m"
#define WHITE        "\033[1;37m"

int main() {
    printf(RED "This is red text.\n");
    printf(LIGHT_RED "This is light red text.\n");
    printf(GREEN "This is green text.\n");
    printf(LIGHT_GREEN "This is light green text.\n");
    printf(BLUE "This is blue text.\n");
    printf(LIGHT_BLUE "This is light blue text.\n");
    printf(DARK_GRAY "This is dark gray text.\n");
    printf(CYAN "This is cyan text.\n");
    printf(LIGHT_CYAN "This is light cyan text.\n");
    printf(PURPLE "This is purple text.\n");
    printf(LIGHT_PURPLE "This is light purple text.\n");
    printf(BROWN "This is brown text.\n");
    printf(YELLOW "This is yellow text.\n");
    printf(LIGHT_GRAY "This is light gray text.\n");
    printf(WHITE "This is white text.\n");
    printf(NONE "This is normal text.\n");

    return 0;
}
```

# vsprintf

## 1.场景考虑

考虑一个问题，在做`STM32`智能锁项目的时候，需要日志打印输出。而打印输出是通过串口实现打印的。

且日志都是都过宏定义的形式实现的，如：

```c
#define LOGDEBUG(format, ...) \
    do { \
        char buff[128]; \
        snprintf(buff, sizeof(buff), format, __VA_ARGS__); \
        printf("[DEBUG] %s\n", buff); \
    } while(0)
```

但是有时候do while里面要进行大量处理，如果还是用宏，在预处理展开时会导致代码体异常庞大，此时就要用到函数，那么函数形参应该如何定义，而可变参数又该如何接收呢？此时就可以用到`vsprintf`了。

## 2.`va_list`可变参数列表的容器

`va_list` 是一个**类型**，用于存储可变参数的信息。它本质上是一个**指针**，指向函数调用栈中的参数区域。

```c
#include <stdarg.h>
va_list args;  // 定义一个可变参数列表
```

## 3.`va_start`初始化参数列表

`va_start` 宏用于**初始化 `va_list` 对象**，使其指向第一个可变参数。

```c
void va_start(va_list ap, last_param);
//参数
	//- ap：va_list类型的变量，将被初始化为指向可变参数的起始位置。
	//- last_param：函数声明中的最后一个固定参数（即...之前的那个参数）。
```

**工作原理**
`va_start` 通过计算 `last_param` 的位置，推断出可变参数的起始地址，并将 `ap` 指向该地址。

## 4.`va_arg`获取下一个参数

`va_arg` 宏用于**获取当前参数的值，并将指针移动到下一个参数**。

```c
type va_arg(va_list ap, type);
//参数
  //- ap：已初始化的va_list对象。
  //- type：要获取的参数的类型（如int、char）。

//返回值：当前参数的值，类型为type
```

**工作原理**：

1. 根据 `type` 的大小（如 `int` 通常为 4 字节），从 `ap` 指向的位置读取数据。
2. 将 `ap` 指针向后移动 `type` 的大小，指向下一个参数。

## 5.`va_end`清理资源

`va_end` 宏用于**清理 `va_list` 对象**，确保资源正确释放。

```c
void va_end(va_list ap);
//参数
	//-ap：已初始化的va_list对象。
```

**工作原理**：
将 `ap` 置为无效值（如 NULL），防止误用。在使用完 `va_list` 后必须调用，否则可能导致内存泄漏或栈损坏。

## 6.完整示例

### 1.`vsprintf`

```c
void Label::setfmttext(const char *fmt, ...)
{
    char txt[64];
    va_list ap;
    memset(txt, '\0', 64);
    va_start(ap, fmt);
    vsprintf(txt, fmt, ap);
    va_end(ap);
}
```

### 2.其他场景

```c
#include <stdarg.h>
#include <stdio.h>

int sum(int count, ...) {
    va_list args;
    int total = 0;
    
    // 1. 初始化参数列表，last_param是count
    va_start(args, count);
    
    // 2. 循环获取所有参数
    for (int i = 0; i < count; i++) {
        // 获取一个int类型的参数
        int num = va_arg(args, int);
        total += num;
    }
    
    // 3. 清理参数列表
    va_end(args);
    
    return total;
}

int main() {
    int result = sum(3, 10, 20, 30);  // 计算10+20+30
    printf("Sum: %d\n", result);      // 输出60
    return 0;
}
```

## 7.关键注意事项

1. **固定参数的必要性**
   可变参数函数**必须至少有一个固定参数**（如 `sum` 中的 `count`），用于指示可变参数的数量或类型。否则，函数无法知道参数的边界。
2. **类型安全**
   `va_arg` 的 `type` 参数必须与实际参数类型匹配，否则会导致未定义行为（如整数截断、指针错误）。
3. **参数遍历顺序**
   参数只能按顺序从第一个可变参数开始读取，不能随机访问或回溯。
4. **内存管理**
   `va_list` 对象不需要显式分配内存，但必须在使用后调用 `va_end`。

## 8.常见应用场景

1. **格式化函数**（如 `printf`、`sprintf`）
2. **日志系统**（收集不定数量的日志信息）
3. **国际化工具**（根据语言选择不同的格式字符串）
4. **错误处理函数**（报告不同类型的错误信息）

## 9.总结

`va_list`、`va_start` 和 `va_end` 是 C 语言处理可变参数的核心机制，通过指针操作实现了参数的动态获取。理解它们的工作原理，是设计灵活、高效接口的关键。但需特别注意类型安全和参数边界问题，避免潜在的错误。
