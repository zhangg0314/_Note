# 指令、伪指令、伪操作的区别

## 1. ARM指令（Instruction）

CPU硬件直接执行的机器码。每条对应一个固定二进制编码，汇编器原样翻译。

```asm
MOV R0, #1      @ 机器码: 0xE3A00001
ADD R1, R0, R0  @ 机器码: 0xE0801000
```

- ARM模式32位编码，Thumb模式16位编码
- 汇编器原样翻译成机器码
- 运行时CPU逐条取指执行

### 1.2 伪指令（Pseudo-instruction）

汇编器提供的助记符，**没有对应机器码**，汇编器翻译成一条或多条真实指令。

```asm
LDR R0, =0x12345678   @ 伪指令，展开为 LDR + literal pool
NOP                   @ 展开为 MOV R0, R0
LDR R0, label         @ PC相对寻址的真实LDR，但带=号是伪指令
PUSH {R1,R2,R3}       @ 展开为 STMDB SP!, {R1,R2,R3}
POP {R1,R2,R3}        @ 展开为 LDMIA SP!, {R1,R2,R3}
```

常见伪指令：

| 伪指令 | 展开为 |
|--------|--------|
| `LDR Rd, =const` | LDR + literal pool 或 MOV/MVN |
| `ADR Rd, label` | ADD/SUB 基于PC |
| `NOP` | `MOV R0, R0` |
| `PUSH {regs}` | `STMDB SP!, {regs}` |
| `POP {regs}` | `LDMIA SP!, {regs}` |

### 1.3 伪操作（Directive / Assembler Directive）

**控制汇编器行为**，不生成机器码。告诉汇编器"怎么做汇编"，而非"做什么运算"。运行时不存在。

```asm
.text                @ 以下代码放代码段
.data                @ 以下放数据段
.global main         @ main符号导出
.byte 0x12, 0x34    @ 直接放字节数据
.word 0x12345678    @ 放32位数据
.equ COUNT, 10      @ 定义常量
.align 4             @ 4字节对齐
```

### 1.4 三者对比

| | ARM指令 | 伪指令 | 伪操作 |
|---|---------|--------|--------|
| 生成机器码 | 是 | 是（汇编器展开后） | 否 |
| CPU执行 | 是 | 是（展开后） | 否 |
| 作用 | 算术/逻辑/访存 | 简化编码，汇编器展开 | 控制汇编过程（段、符号、对齐、数据） |
| 举例 | `ADD`, `LDR`, `STR` | `LDR R0,=val`, `NOP`, `PUSH` | `.text`, `.word`, `.global`, `.equ` |
| 运行时存在 | 是（在代码段） | 否（被替换为真指令） | 否（仅编译期存在） |

## 2. 结合运行内存（SRAM/DDR）的完整理解

### 2.1 内存里的真相

SRAM/DDR里**只有字节**，没有"指令"和"数据"的硬件区别。同一块内存：

```
地址        内容（hex）      CPU取指执行          CPU用LDR读取
─────────────────────────────────────────────────────────────
0x0000_0000: E3A00001       MOV R0, #1          拿到 0xE3A00001
0x0000_0004: E0801000       ADD R1, R0, R0      拿到 0xE0801000
0x0000_0008: 12345678       非法指令(乱执行)     拿到 0x12345678
```

**同一批字节，用途取决于怎么访问它。**

### 2.2 从源码到内存的完整流程

```
┌─ 源码 (.s文件) ─────────────────────────────────┐
│                                                  │
│  .text                    ← 伪操作：进代码段       │
│  MOV R0, #1               ← 指令：CPU执行         │
│  LDR R1, =0x12345678      ← 伪指令：汇编器展开     │
│  ADD R2, R0, R1           ← 指令：CPU执行         │
│  B loop                   ← 指令：CPU执行         │
│                                                  │
│  .data                    ← 伪操作：进数据段       │
│  .global table            ← 伪操作：导出符号       │
│  table:                   ← 伪操作：定义标签       │
│  .word 0xAAAA             ← 伪操作：放原始数据     │
│  .word 0xBBBB             ← 伪操作：放原始数据     │
│  .equ SIZE, 2             ← 伪操作：常量定义       │
└──────────────────────────────────────────────────┘
           │
           ▼ 汇编器（as）处理
┌─ 目标文件 (.o) ──────────────────────────────────┐
│  .text 段:                                        │
│    00: E3A00001        (MOV R0, #1)               │
│    04: E59F1xxx        (LDR R1, [PC, #offset])   │ ← 伪指令展开
│    08: E0802001        (ADD R2, R0, R1)           │
│    0C: EAxxxxxx        (B loop)                   │
│  literal pool:                                   │
│    10: 12345678        (常量数据)                  │
│                                                  │
│  .data 段:                                        │
│    00: 0000AAAA                                     │
│    04: 0000BBBB                                     │
└──────────────────────────────────────────────────┘
           │
           ▼ 链接器（ld）链接
┌─ 可执行文件 (.elf) ──────────────────────────────┐
│  代码段 → 加载到 0x0000_0000 (Flash/SRAM)         │
│  数据段 → 加载到 0x2000_0000 (SRAM/DDR)           │
└──────────────────────────────────────────────────┘
           │
           ▼ 运行时加载到物理内存
┌─ 物理内存布局 ───────────────────────────────────┐
│                                                  │
│  Flash/SRAM 代码区 (0x0000_0000):                 │
│  ┌──────────┬──────────┐                         │
│  │ E3A00001 │ MOV R0,#1│ ← 指令，CPU取指执行     │
│  ├──────────┼──────────┤                         │
│  │ E59F1xxx │ LDR ...  │ ← 指令（伪指令展开后）  │
│  ├──────────┼──────────┤                         │
│  │ E0802001 │ ADD ...  │ ← 指令                 │
│  ├──────────┼──────────┤                         │
│  │ 12345678 │ 常量数据  │ ← 不是指令，是数据     │
│  └──────────┴──────────┘                         │
│                                                  │
│  SRAM/DDR 数据区 (0x2000_0000):                   │
│  ┌──────────┬──────────┐                         │
│  │ 0000AAAA │ table[0] │ ← 数据，LDR/STR访问    │
│  ├──────────┼──────────┤                         │
│  │ 0000BBBB │ table[1] │ ← 数据                 │
│  └──────────┴──────────┘                         │
└──────────────────────────────────────────────────┘
```

### 2.3 关键理解

- **伪操作不留痕迹**：`.word 0x12345678` 运行时内存里就是4字节 `78 56 34 12`
- **伪指令被消灭**：`LDR R0,=0xFF` 在.o文件里已是真指令 + literal pool条目
- **指令活到运行时**：只有真指令的机器码存在于代码段，CPU的PC指针逐条取指执行

## 3. 段标识与默认段规则

### 3.1 没有段标识时的默认行为

没写任何段标识时，**默认进 `.text`（代码段）**。

```asm
@ start.S — 没写 .text
_start:
    MOV R0, #1      @ 默认属于 .text
    LDR R1, =0xFF   @ 默认属于 .text
```

等价于：

```asm
.text               @ 隐含的
_start:
    MOV R0, #1
    LDR R1, =0xFF
```

### 3.2 为什么start.S通常不写.text

1. 启动代码全是可执行指令，没有数据，不需要切段
2. 链接脚本(.ld)控制段的最终布局和地址
3. 编译命令指定入口（`-e _start`），链接器知道从哪开始

### 3.3 混合内容时必须写段标识

一旦有数据混在代码里，必须显式切段或用literal pool：

```asm
@ 错误写法 — 数据混在代码段执行流里
_start:
    MOV R0, #1
    .word 0x12345678    @ CPU会尝试执行这个数据！
    ADD R1, R1, #1

@ 正确写法1 — 切段
.text
    MOV R0, #1
    B skip_data
.data
    my_data:
    .word 0x12345678
.text
skip_data:
    ADD R1, R1, #1

@ 正确写法2 — literal pool
_start:
    MOV R0, #1
    LDR R1, =0x12345678
    ADD R2, R0, R1
    .ltorg              @ 强制放literal pool在这里
```

### 3.4 .text段不等于只能放指令

`.text`段可以混入数据，**只要CPU不会顺序取指到那块数据就行**。

U-Boot向量表示例：

```asm
start: b    reset
    ldr    pc, _undefined_instruction
    ldr    pc, _software_interrupt
    ldr    pc, _prefetch_abort
    ldr    pc, _data_abort
    ldr    pc, _not_used
    ldr    pc, _irq
    ldr    pc, _fiq

_undefined_instruction: .word _undefined_instruction
_software_interrupt:    .word _software_interrupt
_prefetch_abort:        .word _prefetch_abort
_data_abort:            .word _data_abort
_not_used:              .word _not_used
_irq:                   .word _irq
_fiq:                   .word _iq
```

这些`.word`放在`.text`段，CPU不会顺序执行到它们——每条`LDR PC`执行后PC已跳走。`.word`存的是地址常量，被上面的`LDR PC`当数据读取。

## 4. Literal Pool（文字池）

### 4.1 为什么需要

ARM指令32位编码，放不下大常量。

```asm
MOV R0, #0xFF         @ OK，8位立即数，编码得下
MOV R0, #0x12345678   @ 不行！ARM指令只放得下8位旋转立即数
```

ARM立即数编码规则：**8位值 + 偶数位旋转**。`0x12345678`放不下。

### 4.2 Literal Pool工作原理

汇编器在代码段里**偷偷挖个坑埋常量数据**，用`LDR PC-relative`读取。

```asm
    MOV R1, #1
    LDR R0, =0x12345678   @ 伪指令
    ADD R2, R0, R1
    .ltorg                @ 在这里埋常量
```

汇编器翻译后：

```
地址      内容                    说明
─────────────────────────────────────────────
0x00:     MOV R1, #1              真指令
0x04:     LDR R0, [PC, #16]      真指令，从PC+16读数据
0x08:     ADD R2, R0, R1          真指令
0x44:     12345678                ← literal pool
```

### 4.3 为什么不会被CPU误执行

汇编器保证literal pool放在**执行流到不了的地方**：

1. 放在**跳转指令后面**
2. 放在函数末尾（函数通过`BX LR`返回）
3. 用`.ltorg`手动指定位置

```asm
my_func:
    LDR R0, =0x12345678
    BX LR              @ 函数返回，不会执行到下面
    .ltorg              @ literal pool安全放这
```

### 4.4 Literal Pool vs .data段

| | Literal Pool | .data段 |
|---|---|---|
| 位置 | 混在代码段里 | 独立数据段 |
| 可写 | 只读（在Flash里） | 可写（在RAM里） |
| 用途 | 常量、地址常量 | 全局变量、可修改数据 |
| 访问方式 | PC相对LDR | 绝对地址LDR/STR |

## 5. 符号与.global

### 5.1 符号的本质

符号 = 地址，没有别的。

```
源码                    符号表（链接后）
─────────────────────────────────────────
_start:                 _start = 0x00000000
    MOV R0, #1          
    ADD R1, R0, #1      
my_func:                my_func = 0x00000008
    BX LR               
my_var:                 my_var = 0x20000000
    .word 0x1234        
```

引用符号 = 引用地址：

```asm
B _start          @ 跳到地址0x00000000
LDR R0, =my_func  @ R0 = 0x00000008
LDR R1, =my_var   @ R1 = 0x20000000
LDR R2, [R1]      @ 从地址0x20000000读数据
```

### 5.2 .global的作用

`.global`**不控制放哪个段，只控制符号可见性**。

```asm
.global _start      @ 导出符号，链接器可见
.global my_func     @ 导出符号

.text
_start:             @ _start在.text段
    MOV R0, #1

.data
my_var:             @ my_var在.data段
    .word 0x1234
```

符号在哪段取决于它前面的段声明，`.global`只告诉链接器"这个符号别人可以用"。

### 5.3 符号可见性规则

| 声明 | 本文件 | 其他.o文件 | 链接器全局符号表 |
|------|--------|-----------|----------------|
| 不加.global | 可见 | 不可见 | 不导出 |
| .global _xxx | 可见 | 可见 | 导出 |

汇编符号**默认local**，C函数**默认global**。这是区别。

```asm
@ a.S
_start:            @ 不加.global → 只有a.S自己能用
    MOV R0, #1

@ b.S
    B _start       @ 链接错误！找不到_start
```

```asm
@ a.S
.global _start     @ 加了 → b.S也能用
_start:
    MOV R0, #1
```

## 6. 链接器如何查找符号（重定位机制）

### 6.1 两阶段查找

**阶段1：汇编器（as）— 生成重定位条目**

汇编器处理单个.s文件时，不知道符号在哪、地址是啥。

```
源码: BL _main
        ↓
目标文件(.o):
  机器码: BL 0x00000000（地址先填0）
  重定位表: { 偏移0x04, 符号_main, 类型R_ARM_CALL }
```

**阶段2：链接器（ld）— 填地址**

链接器收集所有.o文件：

```
a.o: 引用_main（重定位条目）
b.o: 定义_main（.global _main: ...）
       ↓
链接器算出 _main = 0x08001000
       ↓
回头改a.o的机器码:
  BL 0x00000000 → BL 0x08001000
```

### 6.2 完整流程

```
┌─ a.S ──────────────────────┐  ┌─ b.S ────────────────────┐
│ BL _main                   │  │ .global _main            │
│ ...                        │  │ _main:                   │
└─────────────┬──────────────┘  │     MOV R0, #1           │
              │                 │     BX LR                │
              ▼                 └─────────────┬────────────┘
┌─ a.o ──────────────────────┐               │
│ 代码: BL 0x00000000 (待填)  │               │
│ 重定位: _main@偏移0x04      │               │
└─────────────┬──────────────┘               │
              │                 ┌─ b.o ──────┴────────────┐
              │                 │ _main = 0x00000008       │
              │                 └─────────────┬────────────┘
              ▼                               ▼
         ┌────────────────────────────────────────┐
         │              链接器 (ld)                │
         │ 1. 合并所有.text段，分配地址             │
         │ 2. 建立全局符号表                       │
         │ 3. 修补重定位                           │
         └────────────────────────────────────────┘
                           │
                           ▼
┌─ 最终可执行文件 ───────────────────────────────┐
│ 0x00000000: BL 0x00000008  → 跳到_main        │
│ 0x00000008: MOV R0, #1     ← _main在这里      │
│ 0x0000000C: BX LR                              │
└───────────────────────────────────────────────┘
```

### 6.3 同文件 vs 跨文件

| 情况 | 处理 |
|------|------|
| 符号在同文件定义 | 汇编器直接算出偏移，不用重定位 |
| 符号在别的.o文件 | 汇编器留重定位条目，链接器填地址 |
| 符号找不到 | 链接器报错：`undefined reference to _xxx` |

## 7. 链接脚本的作用

段标识告诉汇编器"归哪类"，但**最终放什么地址由链接脚本(.ld)决定**：

```ld
/* linker script */
MEMORY {
    FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 256K
    RAM (rwx)  : ORIGIN = 0x20000000, LENGTH = 64K
}
SECTIONS {
    .text : { *(.text) } > FLASH
    .data : { *(.data) } > RAM AT> FLASH
}
```

链接脚本把所有.o文件里的同名段合并，分配地址。
