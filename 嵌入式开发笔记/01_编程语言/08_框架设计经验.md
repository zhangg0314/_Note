# 框架设计经验

记录从实际项目中提炼的设计方法。每条先写可迁移的经验，再写项目示例和使用边界。

## 1. 在运行模式入口选择实现，让业务使用统一接口

### 经验总结

设计框架时，先分清**稳定的业务意图**和**随运行环境变化的实现**。例如，业务只需要表达“启动进度已推进”，但前台、SystemV、systemd 对这句话的处理方式不同。

1. 为稳定的业务意图定义小而明确的接口，让业务依赖接口，而非具体环境。
2. 在知道运行模式的入口处选择实现，并把实现对象传给业务。模式判断集中在这一层，业务代码只调用接口。
3. 某种模式允许某项操作不产生效果时，可以使用**空对象模式**：提供一个满足接口、但操作为空的实现。这样调用方无需反复判断对象是否存在。
4. 某种模式才需要的外部库，可以在进入该模式时**按需加载**。动态加载成功后再使用函数指针，加载失败则按该模式的要求明确处理。

这两种方法解决的是不同问题：空对象统一调用方式；按需加载控制外部依赖。它们可以组合，但不必绑定使用。集中选择实现也不会消除模式判断，只会让判断留在容易检查的入口。

**设计时自问：** 哪些操作是业务真正需要的？哪些行为因环境而变？模式由谁确定？缺少能力时是允许忽略、返回错误，还是停止启动？接口的返回值是否能表达真实状态？

### 示例：AppEntry 的进度报告

`AppEntry` 让业务的 `Startup()` 统一接收 `IProgressReporter&`。框架在运行入口选择报告器：

| 运行模式 | 选择的实现 | 效果 |
| --- | --- | --- |
| 前台 | `NullReport` | 进度报告调用不产生外部效果 |
| SystemV | `NullReport` | 进度报告调用不产生外部效果 |
| systemd | `SystemdProgressReporter` | 通过 `sd_notify` 向 systemd 报告状态 |

下面是与源码对应的简化示意，突出选择位置和调用关系：

```cpp
// 框架入口：根据本次启动参数进入相应运行函数。
// RunNormal() / RunSvcSystemV():
m_reporter.reset(new NullReport());

// RunSvcSystemd():
SystemdProgressReporter *report = new SystemdProgressReporter();
m_reporter.reset(report);
if (!*report) {
    return 1; // systemd 模式需要通知能力，加载失败则不继续启动
}

// 各运行函数均将选好的实现交给业务：
Proc->Startup(*m_reporter, m_vm, log);
```

于是业务初始化代码只表达意图：

```cpp
bool Startup(IProgressReporter &reporter,
             boost::program_options::variables_map &vm,
             log4cplus::Logger &log)
{
    reporter.IncProgress(1, 30000);
    // 初始化业务组件...
    return true;
}
```

`SystemdProgressReporter` 的构造函数在 systemd 路径上调用 `dlopen("libsystemd.so.0", RTLD_LAZY)`，再用 `dlsym(..., "sd_notify")` 取得函数指针；析构时调用 `dlclose()`。因此，前台和 SystemV 模式不需要在启动时加载这个库。`#include <systemd/sd-daemon.h>` 只提供声明；直接调用 `sd_notify()` 通常还需要链接 `-lsystemd`，并使程序启动依赖相应动态库。

### 使用边界

- 空对象只适合**允许忽略**的操作。`NullReport::CurrentStatus()` 固定返回 `Status_Stoped`，不是实际进程状态；业务不能拿它判断服务是否正在运行。
- 按需加载后必须检查库句柄和函数指针。`AppEntry` 在 systemd 模式下检查报告器是否可用，失败就返回错误。
- 接口应描述业务所需的能力。若未来某种模式必须反馈报告失败，现有 `void` 接口就不足以表达结果，需要重新审视契约。

源码位置：`Shared/AppEntry/IProgressReporter.h`、`Shared/AppEntry/UnixApplicationBase.h`、`Shared/AppEntry/SystemdProgressReporter.cpp`。
