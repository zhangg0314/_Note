# ——USB协议——

# 物理特性

## 1.引脚

一条USB传输线分别由地线、电源线、D+和D-四条线构成，D+和D-是差分输入线，它使用的是3.3V的电压(与CMOS的5V电平不同)，而电源线和地线可向设备提供5V电压，最大电流为500mA(可以在编程中设置)。

| 引脚标号 | 信号名称   | 缆线颜色 |
| :------: | ---------- | :------: |
|    1     | Vcc        |    红    |
|    2     | Data- (D-) |    白    |
|    3     | Data+ (D+) |    绿    |
|    4     | GND        |    黑    |

```txt
USB设备可以直接和HOST通信，或者通过Hub和Host通信。一个USB系统中仅有一个USB主机，设备包括USB功能设备和USB HUB(扩展坞)，最多支持127个设备。物理连接指的是USB传输线。在USB 2.0系统中要求使用屏蔽双绞线。
```

## 2.USB 信号（差分信号）

使用差分信号进行数据传输，有效的降低外接带来的干扰。

## 3 .USB 信号编码（NRZI）

USB 数据传输的传输使用反向不归零编码进行传送（NRZI），而UART，IIC等用的是NRZ编码，这样就少一根时钟线也能同步。

反向不归零编码方式可以保证数据的完整性，而且不要求传输过程中由独立的时钟信号，且不会像归零编码那样每传完1bit就归零来占据一位浪费带宽。

## 4.USB 字节序

LSB 先发，MSB 后

## 5.USB 设备检测

USB1.0和USB1.1支持1.5Mb/s的低速模式和12Mb/bs的全速模式。在USB2.0以上支持480Mb/s的高速模式。

当 USB 设备接入系统时刻，系统通过检测 USB 上的 D+或者D- 线上的上拉电阻的方式来识别低速和全速设备。如下图所示，当主机端没有设备接入的时候，其D+和D-的下拉电阻使得其电压几乎为 0V；当全速/低速设备接入后，在D+或者D-端的上拉电阻会使得D+/D-出现高电平，而另外一根是低电平。主机端便知道有设备插入。

![img](D:..\figure\c3226ba58a6555420d06f77dfefb1ab6.png)

对于高速设备，和全速设备一样，在D+上存在上拉电阻，对于高速设备的的识别，主机先把高速设备检测为全速设备，然后再通过“Chirp 序列”的总线握手机制来识别高速和全速设备。

# 通信协议

## 1.组成关系

域组成了包，不同的域，组成了不同类型的包（Token、Data、HandShake）。

包组成了事务，多个包一起组成了一个事务（SetUp事务，IN 事务，OUT 事务）

事务组成了传输，多个事务，进而组成了不同类型的传输（控制传输，中断传输，批量传输，同步传输）

## 2.包

### 1.包的组成

包（Packet）是USB系统中信息传输的基本单元，所有数据都是经过打包后在总线上传输的。数据在 USB总线上的传输以包为单位，包只能在帧内传输。高速USB总线的帧周期为125us，全速以及低速 USB 总线的帧周期为 1ms。帧的起始由一个特定的包（SOF 包）表示，帧尾为 EOF。EOF不是一个包，而是一种电平状态，EOF期间不允许有数据传输。 

包是USB总线上数据传输的最小单位，不能被打断或干扰，否则会引发错误。若干个数据包组成一次事务传输，一次事务传输也不能打断，属于一次事务传输的几个包必须连续，不能跨帧完成。一次传输由一次到多次事务传输构成，可以跨帧完成。

USB包由五部分组成，即**同步字段（SYNC**）、**包标识符字段（PID）**、**数据字段**、**循环冗余校验字段（CRC）**和包结尾字段（EOP），包的基本格式如下图：

![img](..\figure\8f9fc4429543b57dbd33b4e75d37be8e.png)

其中数据字段有三种：

- ADDR地址字段： **IN/OUT/SETUP令牌包**
- FrameNum帧序号字段：**SOF令牌包**
- DATA数据字段：**DATA数据包**

### 2.PID 域

#### 1.介绍

**PID（Packet Identifier，包标识符）域**是 USB 数据包结构中的关键部分，用于标识数据包的类型和用途，确保通信双方正确解析数据。不同的 PID 标识了不同类型的USB包。由**四位标识符 + 四位标识符反码**构成。这里只用（PID0~4）,PID4~7是PID0~4的取反，用来校验 （偶检验）PID。

![img](..\figure\0fc72bcfab3e315fdc7eb07f5e3f2681.png)

#### 2.包分类

根据 PID 域的不同，主要将 USB 的包分为了 4 类：

1. **令牌包（Token）** 

    - **OUT**（`0001`）：主机向设备的端点发送数据，并包含了设备地址和标号。
    - **IN**（`1001`）：主机请求从设备的端点接收数据，并包含了设备地址和标号。
    - **SETUP**（`1101`）：主机向设备发送控制命令（用于控制传输的初始阶段），用于主机对设备的初始化。
    - **SOF**（`0101`）：帧开始信号（每 1ms 发送一次，用于同步，包含帧编号），并且包含了相应的帧号。
2. **数据包（Data）** 

    - **DATA0**（`0011`）偶数据包
    - **DATA1**（`1011`）：奇数据包，用于交替传输数据，通过编号区分不同批次的数据，解决数据重传或丢失的问题（USB 协议中采用数据翻转机制）。
    - **DATA2**：高速设备的 PID 的同步包。
    - **MDATA**：高速设备分离包，高带宽的同步事务，仅用于高速模式下的批量传输和等时传输。
3. **握手包（HandShake）**
    - **ACK**（`0010`）：接收方确认数据已正确接收。
    - **NAK**（`1010`）：接收方暂时无法接收数据（如缓冲区满），请求重传。
    - **STALL**（`1110`）：端点因错误而停止工作或者端点被禁止或不支持控制管道请求，需要主机干预。
    - **NYET**（0110）：无响应
4. **特殊包（Special）**
    - **PRE**（`0110`）：高速模式下的预同步信号，用于兼容全速设备。
    - **EOP**（包结束信号）：严格来说不算 PID，但作为数据包的结束标志，由电平变化定义。
    - **分裂事务**
    - **PING 测试**：批量传输、控制传输的流控探测。

#### 3.数据传输方向

|  PID  | 数据传输方向 |
| :---: | :----------: |
|  IN   | Device->Host |
|  OUT  | Host->Device |
| SETUP | Host->Device |
| PING  | Device->Host |

### 3.地址域

地址域有两部分组成：【 7bits 的设备地址 ADDR + 4 bits 的端点地址 ENDP】![img](..\figure\bc5750be5303fa093711292c2a491d9f.png)可以知道，USB 系统最大支持链接 127 个设备，每个设备最多 2^4=16 个端点。这个 ENDP 只用在 IN/OUT/SETUP令牌包中。

### 4.Frame Number 帧号域

当USB令牌包的 PID 为 SOF时候，其数据字段必须为11位的帧序列号。

帧号占11位，主机每发出一个帧，帧号都会自加1，当帧号达到0x7FF时，将归零重新开始计数。对于同步传输有重要意义。

### 5.Data 数据域

仅存在于 DATA 信息包，根据不同的传输类型，拥有不同大小的字节（0--1023字节）

### 6.CRC域

用于进行数据的 CRC 校验

## 3.包类型（Packets Type）

### 1.令牌包（Token）

根据域的 PID 描述，令牌包有4种：

令牌包有四种：

- OUT： 通知设备将要输出一个数据包

- IN： 通知设备返回一个数据包
- SETUP： 只用在控制传输中，也是通知设备将要输出一个数据包，与OUT令牌的区别是：只使用DATA0数据包，且只能发到device的控制端点
- SOF： 在每帧开始时以广播的形式发送，针对USB全速设备，主机每1ms/125us产生一个帧，USB主机会对当前帧号进行统计，每次帧开始时通过SOF包发送帧号。

### 2.令牌包格式

- 输入包（IN）、输出包（OUT）和设置包（SETUP）的格式都是一样的：

  ```c
  SYNC + PID + ADDR(7 bits) + ENDP(4bits) + CRC5(五位的校验码)
  ```

- 帧起始包（SOF）的格式

  ```c
  SYNC + PID + 11位FRAM + CRC5(五位的校验码)
  //- SOF包由Host发送给Device
  //- 对于full-speed总线，每隔1.00 ms ±0.0005 ms发送一次；
  //- 对于high-speed总线，每隔125 μs ±0.0625 μs发送一次；
  ```

### 3.数据包（Data）

分为DATA0包和DATA1包，当USB发送数据的时候，如果一次发送的数据长度大于相应端点的容量时，就需要把数据包分为好几个包，分批发送，DATA0包和DATA1包交替发送，即如果第一个数据包是DATA0，那第二个数据包就是DATA1。但也有例外情况，在同步传输中(四类传输类型中之一)。

### 4.数据包格式

所有的数据包都是为DATA0，格式如下

  ```c
  SYNC + PID + 0~1023字节 + CRC16
  ```

### 5.握手包（Handshake）

结构最为简单的包，格式如下

```c
SYNC + PID

//ACK： 传输正确完成
//NAK： 设备暂时没有准备好接收数据，或没有准备好发送数据
//STALL： 设备不能用于传输
//NYET/ERR： 仅用于高速传输，设备没有准备好或出错
```

#  USB描述符

## 1.描述符介绍

USB协议为USB设备定义了一套描述设备功能和属性的有**固定结构**的描述符，这些描述符是 USB 设备向主机报告自身信息（如设备类型、功能、端点配置等）的数据结构。

标准的描述符有设备描述符、配置描述符、接口描述符、端点描述符和字符串描述符，还有其他标准描述符，如类描述符。

当 USB 设备接入主机时，主机会通过**控制传输**（通常使用端点 0）读取这些描述符，从而了解设备的特性并加载合适的驱动程序。

在USB设备枚举过程中，主机端的协议软件需要解析从USB设备读取的所有描述符信息。在USB主向设备发送读取描述符的请求后，USB设备将所有的描述符以连续的数据流方式传输给USB主机。主机从第一个读到的字符开始，根据双方规定好的数据格式，顺序地解析读到的数据流。

USB 描述符是设备与主机之间的 “语言”，通过结构化的数据让主机了解设备的功能和通信规则。不同层级的描述符从整体到细节（设备→配置→接口→端点）逐步展开，最终实现设备的正确识别和配置。在 USB 设备开发中，正确定义描述符是确保设备被主机正常识别的关键，是主机识别和配置设备的基础。

## 2.描述符分类

- **设备描述符（Device Descriptor）**

  描述设备的整体信息，是主机读取的第一个描述符。

- **配置描述符（Configuration Descriptor）**

  描述设备的一种工作配置（设备可能支持多种配置，如低功耗 / 高性能模式）。

- **接口描述符（Interface Descriptor）**

  描述一个功能接口（设备的功能可划分为多个接口，如一个复合设备可能包含键盘和鼠标接口）。

- **端点描述符（Endpoint Descriptor）**

   描述接口下的端点（数据传输的具体通道）。

- **字符串描述符（String Descriptor）**

  提供人类可读的字符串信息（如厂商名称、产品名称、序列号），可选（但推荐实现）。

- **关联描述符（Association Descriptor）**
  主要用于复合设备（Composite Device），将设备中相关的接口（Interface）“分组”，明确哪些接口属于同一个功能子设备，帮助主机正确识别和管理复合设备的各个组件，使主机能够为每个功能单元加载对应的驱动（而非为整个复合设备加载单一驱动）。
  
- **其他特殊描述符**

  - **HID 描述符**：用于 HID（人机接口设备，如键盘、鼠标），指向 HID 报告描述符。
  - **报告描述符**：HID 设备专用，定义设备与主机之间的数据格式（如按键、坐标信息）。
  - **设备限定描述符**：高速设备用于描述其在全速模式下的特性。
  
## 3.描述符加载流程

> [!CAUTION]
>
> 每个USB设备只有一个设备描述符。
>
> 一个设备中可包含一个或多个配置描述符，即USB设备可以有多种配置。
>
> 设备的每一个配置中又可以包含一个或多个接口描述符，即USB设备可以支持多种功能（接口），接口的特性通过描述符提供。
>
> 一设备至少要包含设备描述符、配置描述符和接口描述符，如果USB设备没有端点描述符，则它仅仅用默认管道与主机进行数据传输。

1. 设备接入主机后，主机通过端点 0 发送`GET_DESCRIPTOR`请求，先读取**设备描述符**。
2. 主机根据设备描述符中的配置数量，读取**配置描述符**。
3. 主机解析配置描述符，读取其包含的**接口描述符**和**端点描述符**。
4. （可选）主机读取**字符串描述符**，显示设备的友好名称。
5. 主机根据描述符信息加载匹配的驱动，完成设备枚举。

# USB枚举

## 1.枚举概念

USB 枚举（Enumeration）是设备接入主机后，主机识别设备、获取设备信息并完成配置的过程。整个过程中，设备会经历多个状态切换，USB 协议定义了明确的**状态机**来规范这一流程。

## 2.状态分类及介绍

### 1. 连接状态（Attached）

- **触发条件**：设备物理接入 USB 总线（如插入 USB 接口）。
- **状态特征**：
  - 设备通过 USB 线缆获得供电（总线提供 5V 电压），硬件电路初始化（如内部电源稳定、时钟启动）。
  - 此时设备尚未被主机检测到，仅处于 “物理连接” 状态，不响应任何 USB 命令。
- **状态转换**：设备硬件检测到总线供电稳定后，进入 “上电状态”。

### 2. 上电状态（Powered）

- **状态特征**
  - 设备完成上电初始化，内部电路（如 USB 控制器、端点 0 缓冲区）就绪。
  - 此时设备未被主机复位，无法进行数据通信，仅能检测总线状态（如主机发出的复位信号）。
- **关键动作**：主机通过检测 USB 总线的下拉电阻（全速 / 高速设备在 D+/D - 线上的 15kΩ 下拉电阻）感知到设备接入，随后准备发送复位信号。

### 3. 默认状态（Default）

- **触发条件**：主机向设备发送**复位信号**（总线保持低电平至少 10ms）。
- **状态特征**：
  - 设备接收到复位信号后，进入默认状态，初始化所有寄存器和端点（仅端点 0 可用，其他端点未配置）。
  - 设备获得**默认地址（0x00）**，这是枚举过程中主机与设备通信的临时地址（所有新接入设备的初始地址均为 0x00）。
  - 端点 0 被初始化为**控制传输端点**（支持默认的最大包长：低速设备 8 字节，全速设备 64 字节，高速设备 64 字节），用于后续与主机交互。
- **状态转换**：主机通过默认地址（0x00）与设备的端点 0 通信，开始读取设备描述符并配置地址。

### 4. 地址状态（Address）

- **触发条件**：主机向设备发送**设置地址请求（Set Address）**，为设备分配唯一的 USB 地址（1~127 之间）。
- **状态特征**：
  - 设备接收并存储主机分配的地址，后续通信将使用该地址（不再使用默认地址 0x00）。
  - 此时设备仍未被配置（无有效配置描述符），仅能响应与地址相关的命令和基本的控制传输（如读取描述符）。
  - 端点 0 仍为主要通信接口，其他端点仍未激活。
- **状态转换**：主机使用新地址与设备通信，开始读取设备的配置描述符、接口描述符等详细信息。

### 5. 配置状态（Configured）

- **触发条件**：主机向设备发送**设置配置请求（Set Configuration）**，指定设备使用某一配置（配置描述符中定义的配置编号）。
- **状态特征**：
  - 设备根据主机指定的配置，加载对应的配置参数（如激活接口、端点，设置端点的传输类型、最大包长等）。
  - 所有配置中定义的端点（除端点 0 外）被激活，可开始正常的数据传输（如批量传输、中断传输等）。
  - 设备此时处于 “可用状态”，可响应主机的功能请求（如 U 盘的读写命令、鼠标的中断报告等）。
- **状态转换**：枚举过程完成，设备进入正常工作状态。

### 6. **挂起状态（Suspended）**

- **触发条件**：USB 总线在 3ms 内无数据传输（空闲状态），或主机主动发送挂起命令。
- **状态特征**：
  - 设备进入低功耗模式，关闭非必要电路（如高速时钟、外设模块），仅保留唤醒检测电路。
  - 设备停止响应正常数据传输，但能检测总线活动（如主机发送的唤醒信号或数据）。
- **状态转换**：当总线出现数据传输（如主机发送数据包）或设备自身触发唤醒（如鼠标移动），设备退出挂起状态，恢复到配置状态。

## 3.AT32F407A芯片寄存器

### 1.上电状态

主机需要检测 USB 总线的下拉电阻（全速 / 高速设备在 D+/D - 线上的 15kΩ 上拉电阻）感知到设备接入，随后准备发送复位信号。而此芯片上的USB设备为USBFS，因此需要使能上拉电阻，且使能USB PHY(**实现编码，以及差分信号转换的硬件电路**，负责处理数字信号【编码方式】与物理电信号【电平标识】的转换)，让主机能够检测到。

# USB CDC介绍

## 1.概念介绍

**USB CDC** 是 **USB Communication Device Class**（USB 通信设备类）的缩写，是一种协议规范，是 USB 协议中定义的一种设备类规范，用于让 USB 设备模拟传统的通信接口（如串口、调制解调器等），实现数据传输功能。

## 2.核心作用

简单来说，USB CDC 允许 USB 设备被电脑（或其他主机）识别为 “通信设备”，从而通过标准的串口通信协议（如 UART）进行数据交互。例如：

- 单片机通过 USB 接口连接电脑时，若遵循 CDC 规范，电脑会将其识别为一个 “虚拟串口”（如 Windows 中的 `COMx`，Linux 中的 `/dev/ttyACM0`）；
- 开发者可以像操作传统串口一样，用 `Putty`、`Serial Monitor` 等工具与设备通信，无需额外安装复杂驱动。

## 3.主要特点

1. **模拟传统通信接口**
   最常见的应用是 **USB 转串口**（USB-to-Serial），即通过 CDC 规范让 USB 设备模拟 RS-232/RS-485 等串口，兼容传统串口通信软件（如串口调试助手）。
2. **无需定制驱动（主流系统）**
   Windows、Linux、macOS 等主流操作系统已内置 USB CDC 通用驱动，设备只需遵循规范，即可 “即插即用”，无需用户手动安装驱动（特殊子类可能需要额外驱动）。
3. **支持多种通信模式**
   USB CDC 包含多个子类（Subclass），适应不同通信场景：
   - **ACM（Abstract Control Model）**
     最常用的子类，支持控制信号（如 DTR、RTS）和数据传输，广泛用于单片机、模块（如 ESP32、STM32 的 USB 串口功能）。
   - **Ethernet Networking Control Model**
     用于 USB 以太网适配器（如 USB 网卡）。
   - **AT Command Model**
     模拟调制解调器（Modem）的 AT 指令集，早期用于拨号上网设备。

## 4.典型应用场景

- **嵌入式开发**
  单片机（如 STM32、Arduino Leonardo）通过 USB CDC 模拟串口，与电脑传输调试信息、接收控制命令。
- **物联网设备**
  传感器模块通过 USB CDC 将数据发送到电脑，或接收配置参数。
- **消费电子**
  智能手表、打印机等设备通过 CDC 实现与主机的简单数据交互。

## 5.与传统串口的区别

| 对比项   | 传统硬件串口（如 RS-232）  | USB CDC 虚拟串口                                    |
| -------- | -------------------------- | --------------------------------------------------- |
| 物理接口 | 专用串口（DB9 等）         | USB 接口（Type-A/C 等）                             |
| 传输速率 | 较低（通常最高 115200bps） | 更高（取决于 USB 版本，如 USB 2.0 可达 480Mbps）    |
| 驱动需求 | 可能需要专用驱动           | 主流系统内置通用驱动                                |
| 扩展性   | 受限于硬件接口数量         | 可通过 USB 集线器扩展多个虚拟串口（**比如扩展坞**） |

总之，USB CDC 是一种让 USB 设备便捷实现通信功能的标准，尤其在嵌入式领域，它简化了设备与主机的连接流程，是串口通信在 USB 时代的重要替代方案。

# ——USB实现框架——

# USB Core

## 1.概念

在 USB 协议和硬件架构中，**USB Core（USB 核心）** 是指负责处理 USB 协议核心逻辑、协调各组件工作的关键模块，通常以**硬件电路（如芯片内的控制器）**或**软件驱动（如操作系统中的 USB 核心驱动）**的形式存在。它是 USB 通信的 “中枢系统”，承上启下，确保数据传输符合 USB 协议规范。

## 2.USB Core 的核心功能

1. **协议解析与执行**
   实现 USB 协议的核心逻辑，包括：
   - 解析主机与设备之间的各类数据包（如令牌包、数据包、握手包），理解 PID（包标识符）、地址、端点等关键信息。
   - 执行 USB 传输流程（如控制传输的设置 / 数据 / 状态阶段、批量传输的分包与拼接等），确保数据交互遵循协议规则。
   - 处理设备枚举过程（设备插入后，主机通过 USB Core 完成设备识别、驱动加载、配置信息获取等关键步骤）。
2. **资源管理与调度**
   - 管理 USB 总线上的设备地址（确保每个设备有唯一地址）和端点资源（分配端点编号、监控端点状态）。
   - 调度不同类型的传输（控制传输、批量传输、中断传输、等时传输），根据优先级和实时性要求分配总线带宽（如等时传输优先保障带宽，控制传输优先保障可靠性）。
3. **与硬件 / 软件的交互**
   - **向下对接 USB PHY**：向 PHY 发送数字信号（如待传输的数据），或从 PHY 接收转换后的数字信号，屏蔽物理层的电气特性细节。
   - **向上对接上层软件 / 应用**：在主机端，USB Core 向操作系统提供统一的接口（如 USB 驱动模型），让设备驱动或应用程序能通过标准化 API 访问 USB 设备；在设备端，USB Core 向设备固件提供接口，用于配置端点、处理传输请求等。
4. **错误处理与状态管理**
   - 检测传输错误（如数据包校验失败、超时、端点挂起等），并执行协议规定的恢复机制（如重传、清除挂起状态）。
   - 维护 USB 总线和设备的状态（如总线空闲、传输中、挂起、恢复等），并根据状态变化触发相应操作（如进入低功耗模式）。

## 3.USB Core 的存在形式

- **硬件层面**：在 USB 控制器芯片（如 PC 的 USB 主机控制器、嵌入式设备的 USB 从控制器）中，USB Core 通常是一个硬件模块，以电路逻辑实现协议解析、传输调度等核心功能，提升处理效率，**可以理解为组帧解帧电路逻辑**。
- **软件层面**：在操作系统中（如 Windows 的`usbport.sys`、Linux 的`usbcore`模块），USB Core 表现为核心驱动程序，负责管理 USB 主机控制器、设备枚举、驱动匹配等系统级功能，是连接硬件与上层应用的桥梁，**可以理解为根据硬件层解析结果进行处理的软件逻辑**。

## 4.总结

USB Core 是 USB 系统的 “协议大脑”，其核心作用是**实现 USB 协议的核心逻辑、管理资源、调度传输，并协调上下层交互**。无论是主机端还是设备端，都需要 USB Core 来确保数据传输符合 USB 规范，是 USB 通信不可或缺的核心组件。

简单来说，USB PHY 负责 “信号的物理转换”，而 USB Core 负责 “协议的逻辑执行”，两者配合完成

从数字信号到协议通信的完整流程。

# 默认管道

## 1.默认管道概念

USB 协议中的 “默认管道（Default Pipe）” 是**设备与主机之间在枚举阶段（设备刚插入时）唯一存在的通信通道**，用于设备初始化和配置，即使设备没有其他端点描述符，也能通过它与主机交互。

## 2.默认管道的特性

1. **基于端点 0（Endpoint 0）**
   默认管道本质上是**端点 0 的逻辑抽象**，而端点 0 是所有 USB 设备必须强制实现的端点（其他
2. **生命周期贯穿设备整个连接过程**
   - 设备插入主机后，首先通过默认管道完成枚举（主机读取设备描述符、配置设备）；
   - 即使枚举完成后，默认管道依然存在，用于处理后续的控制命令（如重新配置设备、获取状态等）。
3. **固定的通信规则**
   - 采用控制传输模式，数据包大小受限于端点 0 的`wMaxPacketSize`（通常为 8/16/32/64 字节）；
   - 传输过程严格遵循 “令牌包→数据包→握手包” 的 USB 控制传输流程，确保可靠性。

## 3.默认管道的作用

1. **设备枚举的唯一通道**
   设备刚插入时，主机对设备一无所知（不知道设备类型、支持的端点等），只能通过默认管道（端点 0）发送`GET_DESCRIPTOR`等请求，逐步获取设备信息（如设备描述符、配置描述符），完成识别过程。
2. **设备配置与管理**
   枚举完成后，主机仍通过默认管道向设备发送控制命令，例如：
   - 切换设备的配置（`SET_CONFIGURATION`）；
   - 获取设备状态（`GET_STATUS`）；
   - 重置端点（`CLEAR_FEATURE`）等。
3. **兼容低功能设备**
   对于仅需简单通信的设备（如某些传感器），可以不定义其他端点，完全通过默认管道（端点 0）的控制传输实现数据交互（尽管效率较低，但能简化硬件设计）。

## 4.与 “非默认管道” 的区别

| 特性       | 默认管道（Endpoint 0）          | 非默认管道（如 Endpoint 1-15）    |
| ---------- | ------------------------------- | --------------------------------- |
| 必要性     | 强制存在（所有 USB 设备必须有） | 可选（按需定义）                  |
| 传输类型   | 仅支持控制传输                  | 可支持批量、中断、同步传输        |
| 用途       | 枚举、配置、管理                | 实际数据传输（如文件读写）        |
| 包大小限制 | 通常较小（如 64 字节）          | 可更大（如 512 字节，取决于设备） |

## 5.总结

“默认管道” 是 USB 设备通过端点 0 与主机建立的基础通信通道，是设备从插入到正常工作的 “必经之路”。即使设备没有其他端点描述符（即不支持批量、中断等传输），也能通过默认管道的控制传输完成基本通信，这也是 USB 协议兼容性的重要保障。
