





# 系统移植本质

系统移植本质就是安装系统，在基于 ARM 处理器的开发板上安装 Linux 操作系统。

# 系统移植必要

- 不同架构的处理器指令集不兼容，即便是相同的处理器架构，板卡不同，驱动代码也不兼容。
- 当 Linux 系统装上后，去移植一些应用层的东西，凡是二进制的文件包括 ELF 格式的，都区分 x86 和 ARM 架构，因此涉及到二进制文件的都需要进行移植（比如之前学习`sqlite3`时候移植arm架构的第三方库如`sqlite3`）。
- Linux 是一个通用的内核并不是为某一个特定的处理器架构或板卡设计的，所以从官方获取 Linux 源码后要先经过相应的配置使其与我们当前的硬件平台相匹配后才能进行编译和安装。

# 系统移植过程

以SD卡启动加载方式的开发板为例：

1. 准备 Linux 内核镜像、SD 卡启动盘。
2. 通过拨码开关选择启动方式（SD 启动）。
3. 通过 SD 卡中的引导程序安装系统。
4. 安装 Linux 驱动程序。
5. 安装 Linux 应用程序。

# 传统操作流程

传统操作流程中，开发板的 Linux 系统移植开发会需要开发者自己搞定从"硬件适配"到"软件编译"的所有细节，自己手动整合回零散资源、逐个环节从零调试。这个过程门槛高、耗时长，且容易因资源不匹配或配置错误导致失败。而`SDK`会提前适配好开发板的硬件细节，但没有`SDK`时，必须先自己摸清硬件底细。主要流程如下：

1. 获取并配置交叉编译工具链
2. 查阅硬件信息
3. 适配U-Boot
4. 裁剪定制Linux 内核
5. 构建`rootfs`根文件系统
6. 烧录与调试

# SDK 方式

## 1.`SDK`的概念

`SDK` 全称是 Software Development Kit，即软件开发工具包。它是为了方便开发者开发特定软件或硬件相关程序而打包好的一系列工具、资源的集合。比如创龙开发板的 Linux SDK，里面就包含了开发该开发板 Linux 系统所需的各种关键东西：启动程序（U-Boot）、内核代码（Kernel）、文件系统（Filesystem），还有编译工具、配置脚本等。

## 2.传统流程 vs `SDK` 对比

| 环节 | 无 SDK（传统流程） | 有 SDK |
|:----:|:-------------------:|:------:|
| 资源获取 | 手动从官网/仓库下载 U-Boot、内核、工具链，分散且版本难匹配 | SDK 打包好所有适配资源，解压即可用 |
| 硬件适配 | 自己编写板级代码、设备树，反复查手册调试 | SDK 已提前适配好开发板，设备树、驱动均现成 |
| 编译配置 | 手动 `make menuconfig` 逐项配置，易出错 | SDK 提供现成配置文件，一键编译 |
| 调试效率 | 每个环节出错需逐一排查，周期可能长达数周 | 基础功能已验证，聚焦上层开发 |

## 3.总结

没有 `SDK` 的传统流程，本质是"**还原嵌入式开发的底层细节**"——需要开发者同时掌握硬件原理、底层软件（U-Boot、内核驱动）、交叉编译等技能，且耗时耗力。而 SDK 的核心价值就是"**把这些重复、复杂的底层工作提前做好**"，让开发者跳过"适配硬件、整合资源"的环节，直接聚焦上层应用开发。
