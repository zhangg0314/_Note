# 根文件系统与系统文件

## 1. 根文件系统（rootfs）介绍

根文件系统是内核启动后挂载的**第一个**文件系统，其他文件系统都是在它基础上加载构建的，它是其他文件系统的根。系统引导程序会在根文件系统挂载后从中把一些基本的初始化脚本和服务等加载到内存中去运行，根文件系统本质就是一些文件。

## 2. rootfs 文件目录分析

### 2.1 直接 mkdir 建立的空目录

- **dev**：存放设备文件信息（内核启动后会将设备信息写入该目录，因为内核加载时会加载驱动模块，驱动模块里面有自动 mknod 的代码）
- **proc**：存放进程相关文件（内核启动后会将启动的一些进程的进程信息写入该目录）
- **mnt**：挂载目录（非必要）。Windows 某个文件属于某个磁盘，但 Linux 是某个磁盘属于某个文件
- **root**：超级用户家目录（非必要）
- **sys**：驱动相关文件（内核启动后会将驱动模块、总线等信息写入该目录）
- **tmp**：存放临时文件
- **var**：存放经常变化的数据

### 2.2 需要进行编译配置的目录制作

1. **bin**：存放 mv、ls、cp 以及 BusyBox 的可执行文件等，存放的 Linux shell 命令是 BusyBox（也是 ELF 格式的文件）的**软链接**

2. **sbin**：存放比较重要的 shell 命令

3. **usr**：也包含 bin 和 sbin

4. **linuxrc**：BusyBox 的软连接，是 Linux 内核运行起来后运行的**第一个应用程序**。所有设置 U-Boot 启动参数时有句命令是 `bootcmd init = /linuxrc`

   ```bash
   # 1. 下载 BusyBox，解压编译
   # 2. make menuconfig（一般使用默认配置，需修改编译器类型）
   make           # 编译并生成 BusyBox 可执行文件
   make install   # 生成 BusyBox 到各种命令的软链接，生成 bin/sbin/usr/linuxrc 各目录
   ```

5. **lib**：ARM 架构的动态库文件，**可以直接复制交叉编译工具链里面的**。开发板上只需要有动态库就可以，因为开发板上只能运行程序，不能编译程序。静态库是编译时链接（库生成的二进制代码被包含在 ELF 文件中），动态库是运行时链接。

6. **etc**：内核配置文件，如 init.d 启动目录，里面可以存放一些开机就启动的 shell 命令来作为自启动，是一些文本文件（不区分架构），可以直接复制 Ubuntu 下的。

## 3. 常用系统配置目录/文件

### 3.1 /etc 目录下的文件

`/etc` 目录是 Linux 系统中用于存放系统配置文件的标准目录。许多重要的配置文件都存放在 `/etc` 目录下，这些文件在系统启动时会被不同的服务和程序读取，以完成系统的初始化和配置。

**终端环境配置文件**：当登录系统或新开启一个 ssh 连接启动 bash 进程时，一定会加载这 4 个配置文件：

```bash
vim /etc/profile        # 系统全局环境和登录系统的一些配置
vim /etc/bashrc         # shell 全局自定义配置文件，用于自定义所有 shell
vim /user/.bashrc       # 用于单独自定义某个用户的 bash
vim /root/.bash_profile # 用户单独自定义某个用户的系统环境
```

**网络配置文件**：`/etc/network/interfaces` 是传统的网络配置文件，适用于 Debian 及其衍生发行版。`ifconfig` 命令用于临时配置网络接口的参数，这些配置仅在当前会话中有效，一旦系统重启，临时配置会被丢弃。`/etc/network/interfaces` 文件是系统启动时用于配置网络接口的配置文件，通过它配置的静态 IP 地址会在每次重启后仍然有效。

```bash
# 全局配置
auto lo
iface lo inet loopback

# 网络接口配置
auto eth0
iface eth0 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.1
    dns-nameservers 8.8.8.8 8.8.4.4

auto wlan0
iface wlan0 inet dhcp
    wpa-ssid "your_wifi_ssid"
    wpa-psk "your_wifi_password"
```

### 3.2 /dev 目录下的文件

**空设备文件**：`/dev/null` 是一个特殊的文件，用于将数据彻底丢弃。读取 `/dev/null` 将会立即返回 EOF，而向它写入任何数据将会直接被忽略掉。Linux 中，默认命令、脚本等的标准输出和标准错误输出默认是输出到标准终端上。如果不想在标准终端上显示，可把结果输出到 `/dev/null` 中。

## 4. crontab

### 4.1 基本概念

- **crontab 文件**：存储定时任务的配置文件，每个用户有自己的 crontab 文件。
- **cron 服务**：系统后台守护进程，负责读取 crontab 文件并按计划执行任务。

### 4.2 常用命令

```bash
crontab -e              # 编辑当前用户的 crontab 文件
crontab -l              # 查看当前用户的 crontab 文件
crontab -r              # 删除当前用户的所有 crontab 任务
crontab -u username -l  # 查看指定用户的 crontab（需 root 权限）
```

### 4.3 crontab 文件格式

```txt
* * * * * command
│ │ │ │ │
│ │ │ │ └── 星期 (0-7, 0和7都代表星期日)
│ │ │ └──── 月份 (1-12)
│ │ └────── 日期 (1-31)
│ └──────── 小时 (0-23)
└────────── 分钟 (0-59)
```

**特殊符号**：
- `*`：任意值（匹配所有可能的值）
- `,`：分隔多个值（如 `1,3,5`）
- `-`：定义范围（如 `1-5`）
- `/`：定义间隔（如 `*/2` 表示每 2 个单位）

### 4.4 示例任务

```bash
0 2 * * * /usr/local/bin/backup.sh        # 每天凌晨2点执行备份脚本
15 * * * * /var/log/cleanup.py            # 每小时的第15分钟执行日志清理
0 8 * * 0 service nginx restart           # 每周日早上8点重启服务
0 4 1,15 * * apt-get update && apt-get upgrade -y  # 每月1号和15号执行系统更新
*/5 * * * * /scripts/check_status.sh      # 每5分钟检查一次系统状态
```

### 4.5 注意事项

1. **环境变量**：crontab 执行时的环境变量与登录 shell 不同，建议在脚本中明确指定路径。

   ```bash
   0 0 * * * /usr/local/bin/backup.sh  # 正确：指定完整路径
   ```

2. **日志输出**：任务输出默认发送到用户邮箱，建议重定向到日志文件。

   ```bash
   0 2 * * * /script/run.sh > /var/log/cronjob.log 2>&1
   ```

3. **执行顺序**：多个任务可能并行执行，若有依赖关系需注意。

### 4.6 系统级 crontab

除用户 crontab 外，系统级任务可放在以下目录：

- `/etc/crontab`：系统全局 crontab 文件
- `/etc/cron.d/`：存放独立的 crontab 文件
- `/etc/cron.hourly/`、`/etc/cron.daily/` 等：存放按时间自动执行的脚本

### 4.7 调试技巧

```bash
* * * * * /path/to/script.sh >> /tmp/cron_debug.log 2>&1  # 临时添加调试信息
service cron status                          # 检查 cron 服务状态
tail -f /var/log/syslog | grep cron          # 查看系统日志（Ubuntu/Debian）
tail -f /var/log/cron                        # 查看系统日志（CentOS/RHEL）
```

**在线生成工具**：[crontab.guru](https://crontab.guru/)：输入描述自动生成 cron 表达式。
