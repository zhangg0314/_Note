# 单元测试

## 1.测试意义

在模块化编程码完代码的基础上，需要对模块进行单元测试，确保底层模块一定是正确的才能供上层调用，否则底层出错一般都是从上层开始排查的，需耗费大量时间。

## 2.案例说明

在编写DLMS复用连接池底层模块时，有一个连接过期的超时判断。如果连接超时需要清除对应电表槽位的状态。

```c++
            if (meta->state == ClientSlotState::IDLE && idleTime > idleTimeout)
            {
                LOGDBG("[ClientDaemon] Meter%s idle timeout (%.0fs), recycling connection, slot%d",
                    meterConn.meterAddr.c_str(), std::chrono::duration_cast<std::chrono::seconds>(idleTime).count(), i);
                if (meterConn.conn)
                {
                    meterConn.conn->Close();
                    meterConn.conn.reset();
                }
                meta->clear();
                meterConn.meterAddr.clear();
                addrToSlot_.erase(meterConn.meterAddr);//前面表地址都被clear了，这里还清除个屁
                continue;
            }
```

因为这个小bug导致上层出现两个表同时占用一个槽位，导致DLMS计数器混乱出错。因此在编写任何和业务层无关的底层模块时，都应该提前写好测试程序，让问题都尽量出现在应用上层才更好排查。

## 3.总结

凡是设计到模块化编程的，最好都需要对每个模块编写测试用例，确保模块单独是没问题的。最后才进行模块耦合联动。
