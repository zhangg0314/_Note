# 传统操作流程

## 1.背景介绍

传统操作流程，开发板（比如项目用的创龙开发板）的 Linux 系统开发会回到“**零散资源手动整合、逐个环节从零调试**”的传统流程——这个过程需要开发者自己搞定从“硬件适配”到“软件编译”的所有细节，门槛高、耗时长，且容易因资源不匹配或配置错误导致失败。 以创龙这类嵌入式 Linux 开发板为例，传统流程会拆解为以下 6 个核心步骤，每个步骤都需要手动处理： 

##  2.硬件信息“彻底调研”（无 `SDK` 时的基础前提） 

`SDK `会提前适配好开发板的硬件细节（比如芯片引脚、外设驱动），但没有` SDK `时，必须先自己“摸清硬件底细”，否则后续软件开发会完全“无的放矢”。   

具体操作： 

1. **查芯片手册**
   找到开发板主芯片（比如全志` A40i`、瑞芯微 `RK3506`）的官方 `datasheet`（数据手册）和 reference manual（参考手册），明确芯片的 CPU 架构（如 `ARM Cortex-A7`）、内存接口（`DDR3/DDR4`）、存储控制器（SD/NAND Flash）、外设接口（UART、SPI、Ethernet、USB 等）的硬件地址和配置方式。 

2. **查开发板原理图**
   从创龙或芯片厂商获取开发板的硬件原理图，确认外设的实际连接（比如“网口芯片型号是 DM9000 还是 RTL8189”“LCD 屏的引脚接在芯片哪个 GPIO 上”），避免后续驱动配置与硬件不匹配。 

3. **确认硬件参数**
   记录关键参数（如 DDR 内存大小/频率、Flash 容量/分区、串口波特率等），这些会直接影响后续 U-boot、内核的配置。  

## 3.手动获取底层启动程序U-boot源码并适配 

U-boot 是嵌入式系统的“引导程序”，负责初始化硬件（如内存、存储）、加载 Linux 内核。没有 `SDK` 时，需要自己找 U-boot 源码并修改适配开发板： 

1. **下载通用 U-boot 源码**
   从 U-boot 官方仓库（[https://git.denx.de/cgit/u-boot.git/](https://git.denx.de/cgit/u-boot.git/)）下载对应芯片架构的基础版本（比如针对 ARM 架构的分支），但官方源码通常只支持“芯片评估板”（厂商自己的基础板），不直接支持创龙的定制开发板。 

2. **手动修改 U-boot 适配硬件**
   - **编写“板级配置文件”**
     在 U-boot 源码的 `board/` 目录下，为创龙开发板新增一个文件夹（比如 `board/chuanglong/tl3506-evm/`），编写板级初始化代码（如 `tl3506-evm.c`），实现内存初始化、串口初始化、存储设备识别等逻辑。   

   - **配置设备树（DTS）**
     在 `arch/arm/dts/` 目录下，编写对应开发板的设备树文件（比如 `rk3506-tl3506-evm.dts`），描述硬件资源（如“UART2 对应引脚是 GPIO1_0/1”“网口接在 SPI1 上”），确保 U-boot 能识别硬件。  

   -  **解决编译错误**
     通过 `make tl3506-evm_defconfig`（需自己定义配置文件）、`make` 编译 U-boot，过程中会遇到“某个外设驱动缺失”“引脚定义错误”等问题，需要逐一查手册、改代码调试（比如串口没输出，要检查波特率配置或引脚映射）。 

3. **烧录 U-boot 并验证**
   用专用工具（如 SD 卡烧录工具、USB 下载工具）将编译好的 U-boot 镜像（如 `u-boot.bin`）烧录到开发板的存储设备（SD 卡、NAND Flash），通过串口查看启动日志，确认 U-boot 能正常启动、识别内存和存储。 

## 3.手动获取Linux 内核源码并定制   

Linux 内核是系统的“核心”，负责管理硬件驱动、进程、内存等。没有 SDK 时，内核需要自己下载、配置、编译： 

### 1.下载内核源码

从 Linux 官方仓库（[https://git.kernel.org/](https://git.kernel.org/)）下载对应版本的内核源码（比如创龙 SDK 用的 6.1 版本，就下载 `linux-6.1.x.tar.xz`），或从芯片厂商官网下载“厂商定制版内核”（比官方版多了芯片专属驱动，比如全志的 `sunxi` 驱动、瑞芯微的 rk 驱动）。 

### 2.内核配置

1.**基础配置**：通过 `make menuconfig` 打开图形化配置界面，手动勾选与开发板匹配的选项：

- 架构选择：确认 CPU 架构（如 `ARM`）、子架构（如 `ARMv7`）、具体芯片型号（如 `Rockchip RK3506`）。     

- 驱动配置：逐项勾选外设驱动（比如“Ethernet 驱动选 RTL8189FS”“USB 驱动选 EHCI”“LCD 驱动选对应屏的型号”），如果某个外设没有现成驱动，还需要自己编写驱动代码（比如自定义 GPIO 按键驱动）。

- 文件系统支持：勾选需要的文件系统格式（如 ext4、jffs2、FAT32，用于后续根文件系统挂载）。

2.**设备树适配**：修改或新增内核的设备树文件（与 U-boot 设备树逻辑类似，但需匹配内核驱动接口），确保内核启动后能识别所有硬件（比如网口、USB、LCD）。 

3. **编译内核**：执行 `make zImage`（编译内核镜像）和 `make dtbs`（编译设备树镜像），过程中会遇到“驱动依赖缺失”“配置冲突”等问题，需要反复调整 `menuconfig` 或修改驱动代码。 

4. **验证内核**：将编译好的内核镜像（`zImage`）和设备树镜像（`rk3506-tl3506-evm.dtb`）通过 U-boot 加载（比如从 SD 卡读取），查看串口日志，确认内核能正常启动（无 panic 报错），且能识别外设（如 `ifconfig` 能看到网口 eth0）。  

##  4.手动构建根文件系统

根文件系统是 Linux 系统的“文件目录结构”，包含了系统命令（如 `ls`、`cd`）、库文件（如 `libc`）、初始化脚本（如 `init`）等，没有 SDK 时需要自己从零构建：

### 1.选择构建工具

- 轻量选择：用 **BusyBox**（一个精简的命令行工具集合），通过 `make menuconfig` 勾选需要的命令（如 `ls`、`cp`、`sh`），编译后生成基础的 `/bin`、`/sbin` 目录，再手动创建 `/etc`（配置文件）、`/lib`（库文件）、`/root`（根用户目录）等目录。  

-  复杂选择：用 **Buildroot** 或 **Yocto Project**（自动化构建工具），但需要手动配置构建脚本（比如指定 CPU 架构、工具链、需要安装的软件包），虽然比 BusyBox 自动化，但配置过程仍需熟悉底层逻辑。 

### 2.完善文件系统

  - 添加库文件：将交叉编译工具链中的 `libc`、`libm` 等库文件复制到 `/lib` 目录，否则应用程序（如 `ping`）会因“缺少库文件”无法运行。  

  - 配置初始化脚本：在 `/etc/init.d/` 目录下编写 `rcS` 脚本（系统启动时执行），实现“挂载文件系统”“启动网络服务”“加载驱动模块”等初始化操作（比如 `ifconfig eth0 192.168.1.100` 配置网口 IP）。

  - 测试工具安装：手动交叉编译需要的工具（如 `ping`、`ssh`），复制到 `/bin` 目录，确保系统能执行基本操作。 

### 3.制作文件系统镜像

用 `mkfs.ext4` 等工具将根文件系统目录打包成镜像文件（如 `rootfs.ext4`），方便烧录到存储设备。  

## 5.手动获取并配置交叉编译工具链

嵌入式开发需要“交叉编译”（在 PC 的 Ubuntu 上编译能在开发板 ARM 架构上运行的程序），没有 SDK 时，工具链需要自己找、自己配置： 

1. **下载工具链**：从芯片厂商官网（如瑞芯微官网）下载对应架构的工具链（比如 `arm-linux-gnueabihf-gcc`），或用 `crosstool-ng` 工具手动编译工具链（过程复杂，需要配置编译器版本、库版本等）。

2.  **配置环境变量**：在 Ubuntu 终端中，通过 `export PATH=$PATH:/path/to/toolchain/bin` 配置工具链路径，确保输入 `arm-linux-gnueabihf-gcc -v` 能正常显示版本（验证工具链可用）。 

3. **验证工具链兼容性**：确保工具链版本与内核、根文件系统匹配（比如内核用 gcc 10 编译，根文件系统的库文件也需用同一 gcc 版本编译，否则会出现“ABI 不兼容”错误）。  

## 6.手动烧录与调试（反复试错） 

没有 SDK 提供的“一键烧录脚本”或“调试工具”，需要手动协调 U-boot、内核、根文件系统的烧录和启动逻辑： 

### 1.分区规划

手动对开发板的存储设备（如 SD 卡）分区，比如：   

- 分区 1：存放 U-boot（大小 16MB）；   

- 分区 2：存放 Linux 内核和设备树（大小 64MB）；

- 分区 3：存放根文件系统（剩余空间）。 

### 2.手动烧录

用 `dd` 命令（Ubuntu 下）或专用工具（如 Win32 Disk Imager）将 U-boot、内核、根文件系统分别烧录到对应分区。 

### 3.调试启动逻辑

通过 U-boot 命令行设置启动参数（比如 `setenv bootargs root=/dev/mmcblk0p3 rootfstype=ext4 rw`，指定根文件系统路径），再执行 `bootz` 加载内核。若启动失败（如“根文件系统挂载失败”“内核 panic”），需通过串口日志定位问题：比如根文件系统挂载失败，可能是分区路径错了；内核 panic，可能是设备树与硬件不匹配。

### 4.外设测试

启动成功后，手动测试每个外设（如 `ping 网关` 测试网络、`ls /dev/ttyUSB0` 测试 USB 转串口、`cat /dev/fb0` 测试 LCD），若外设不可用，需回头修改内核驱动或设备树。  

## 7.核心差异

| 环节     | 无 SDK（传统流程）                                           | 有 SDK（创龙提供）                                          |
| -------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| 资源获取 | 手动从官网 / 仓库下载 U-boot、内核、工具链，分散且版本难匹配 | SDK 打包好所有适配资源，解压即可用                          |
| 硬件适配 | 自己编写板级代码、设备树，反复查手册调试                     | SDK 已提前适配好开发板，设备树、驱动均现成                  |
| 编译配置 | 手动 `make menuconfig` 逐项配置，易出错                      | SDK 提供现成配置文件（如 `tl3506_evm_defconfig`），一键编译 |
| 调试效率 | 每个环节出错需逐一排查，周期可能长达数周                     | 基础功能（启动、网口、USB）已验证，聚焦上层开发             |

## 8.总结

没有 SDK 的传统流程，本质是 “**还原嵌入式开发的底层细节**”—— 需要开发者同时掌握硬件原理（能看懂原理图、芯片手册）、底层软件（U-boot、内核驱动）、交叉编译等技能，且耗时耗力（一个新手可能花 1-2 周才能让系统正常启动）。而 SDK 的核心价值就是 “**把这些重复、复杂的底层工作提前做好**”，让开发者跳过 “适配硬件、整合资源” 的环节，直接聚焦上层应用开发（比如编写业务程序、调试外设功能）。

# SDK

SDK 全称是 **Software Development Kit**，也就是 “软件开发工具包”。简单说，它是为了方便开发者开发特定软件或硬件相关程序而打包好的一系列工具、资源的集合。

比如创龙开发板的 Linux SDK，里面就包含了开发该开发板 Linux 系统所需的各种关键东西：像启动程序（U-boot）、内核代码（Kernel）、文件系统（Filesystem），还有编译工具、配置脚本等。有了它，开发者不用自己从零找零散的资源，直接用 SDK 里的工具和资料就能快速搭建开发环境，进行编译、调试等开发工作。
