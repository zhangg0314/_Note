# Web 服务器

## 1.Web 服务器概念

Web 服务器是一种软件或硬件设备，它负责处理客户端（通常是浏览器）发来的 HTTP 请求，并向客户端发送 HTTP 响应。Web 服务器在互联网上起到中介的作用，帮助传输和交换网页和其他资源。

## 2.Web 服务器作用

- **处理 HTTP 请求**
  Web 服务器接收来自客户端的 HTTP 请求，并根据请求的内容作出相应的处理。
- **提供静态资源**
  Web 服务器可以托管和提供静态资源，如 HTML、CSS、JavaScript、图像、音频和视频文件等。
- **执行服务器端代码**
   对于动态网页，Web 服务器可能需要执行服务器端代码，如 PHP、Node.js、Python、Ruby 等，以生成动态内容。
- **处理请求和响应的转发**
   Web 服务器可以根据一些规则将请求转发到其他服务器，例如反向代理服务器、负载均衡器等。

## 3.Web 服务器本质

可以把 Web 服务器想象成 “嵌入式设备的前台接待员”：

- **访客**
  浏览器（手机 / 电脑）发送 HTTP 请求（比如 “我要访问设备的控制页面”“我要调用 LED 控制接口”）；
- **接待员**：Web 服务器（`lighttpd/nginx/cpp-httplib` 内置服务器）接收请求，判断该怎么处理；
  - 如果是静态文件（HTML/CSS/JS）：直接从本地文件夹拿出来返回给访客；
  - 如果是动态请求（API 接口 / PHP 脚本）：转发给后端（`cpp-httplib/PHP `解释器）处理，拿到结果后再返回给访客；
- **最终结果**
  访客（浏览器）拿到响应，渲染成可视化页面。

**关键特征（嵌入式场景重点）**：

1. **基于 HTTP/HTTPS 协议**
   这是 Web 服务器和客户端沟通的 “语言”，必须遵守 HTTP 规范（比如状态码 200/404、请求方法 GET/POST）；
2. **监听指定端口**
   比如 80（HTTP 默认）、443（HTTPS 默认）、8080（嵌入式常用），客户端必须访问对应端口才能通信；
3. **并发处理能力**
   能同时响应多个客户端的请求（嵌入式 Web 服务器一般做轻量级并发，比如 `lighttpd` 的线程池、`cpp-httplib `的线程配置）。

## 4.Web 服务器工作流程

以 `lighttpd + cpp-httplib`为例，完整流程如下：

1. **请求接收**
   `lighttpd`监听 80 端口，收到浏览器的`/api/status`请求；
2. **请求路由**
   `lighttpd`根据配置的反向代理规则，把`/api/*`的请求转发给本地 8080 端口的 `cpp-httplib`；
3. **业务处理**
   `cpp-httplib `执行 C++ 逻辑，读取硬件状态（比如 LED 是否开启）；
4. **响应生成**
   `cpp-httplib`生成 JSON 格式的响应（比如`{"led":true,"temp":25.5}`）；
5. **响应返回**
   `lighttpd` 拿到 `cpp-httplib `的响应，再转发给浏览器；
6. **页面渲染**
   浏览器解析 JSON，更新页面上的 LED 状态和温度数值。

## 5.常见的 Web 服务器

不同 Web 服务器的定位和适用场景差异很大，结合各种需求整理如下：

|    Web 服务器     |            类型             | 资源占用 |                 核心优势                 |                      嵌入式适用场景                      |
| :---------------: | :-------------------------: | :------: | :--------------------------------------: | :------------------------------------------------------: |
|    `lighttpd`     |      独立轻量级服务器       |    低    |    静态文件托管 + 反向代理，配置简单     | 嵌入式 Linux（树莓派 / STM32MP1），需托管前端 + 代理 API |
|      `nginx`      |      独立高性能服务器       |    中    |        高并发、负载均衡，功能丰富        |        嵌入式 Linux（性能较好的设备），高并发需求        |
|   `cpp-httplib`   | 嵌入式 C++ 库（内置服务器） |   极低   | 无额外依赖，编译后体积小，可直接操作硬件 |    纯 C++ 开发、资源受限的嵌入式 Linux / 带 OS 的 MCU    |
| `esp_http_server` |    ESP32/ESP8266 专用库     |   极低   |     适配` WiFi` 芯片，无 OS 也能运行     |         纯 MCU（ESP32/ESP8266），无 Linux 的场景         |
|      Apache       |      独立全功能服务器       |    高    |            插件丰富，兼容性好            |               不推荐（嵌入式资源占用过高）               |

- **核心组合**
  `lighttpd + cpp-httplib`（嵌入式 Linux）—— `lighttpd` 管静态页面和代理，`cpp-httplib` 管高性能 API；
- **极简方案**
  仅用 `cpp-httplib`（直接托管静态文件 + API）—— 适合页面简单、无需复杂代理的场景；
- **纯 MCU 方案**
  `esp_http_server`（ESP32）—— 无 Linux，直接在单片机上跑 Web 服务器。

## 6.Web 服务器 vs 后端服务

|    角色    |                   核心职责                    |          例子          |
| :--------: | :-------------------------------------------: | :--------------------: |
| Web 服务器 | 接收 HTTP 请求、转发 / 返回响应、托管静态文件 |    `lighttpd/nginx`    |
|  后端服务  |      处理业务逻辑（硬件控制、数据计算）       | `cpp-httplib/PHP 脚本` |

**关键区别**：

- Web 服务器只负责 “转发和传递”，不处理具体业务逻辑；
- 后端服务只负责 “处理逻辑”，不一定需要懂 HTTP（比如` cpp-httplib `内置了 HTTP 服务器，所以既能处理逻辑也能当 Web 服务器）。
