# 清中断标志位解决编译警告

Keil中，有时候需要读状态寄存器或者写数据寄存器位来清中断状态位，但我定义一个变量来解释读的数据，也仅仅只是为了清状态位，并不实际使用该变量，但编译器会有警告compiling variable "was set but never used，该如何解决或者换种方式清状态位？

在 Keil 中处理 “仅为清除中断标志位而读取寄存器，但变量未使用导致警告” 的问题，有多种既规范又能避免编译器警告的方法，本质是让编译器明确 “此变量的存在是故意的，无需警告”。以下是常用解决方案：

## 1.使用 `(void)` 强制转换

这是最简洁的方法，通过将读取操作的结果强制转换为 `void`，明确告知编译器 “该值无需使用”，从而消除警告：

```c
// 清除串口空闲中断标志位（以STM32为例）
if (USART_GetITStatus(USART1, USART_IT_IDLE) != RESET) {
    // 直接读取寄存器并强制转换为void，无需定义变量
    (void)USART1->SR;  // 读状态寄存器（清除标志位第一步）
    (void)USART1->DR;  // 读数据寄存器（清除标志位第二步）
}
```

- **原理**：`(void)` 会丢弃表达式的结果，编译器会认为 “开发者知道该值未被使用”，因此不产生警告。
- **适用场景**：所有需要 “读寄存器清标志位” 的场景，代码简洁直观。

## 2.使用 `UNUSED` 宏标记

在工程中定义一个通用的 `UNUSED` 宏（通常放在公共头文件中），用于标记 “故意未使用的变量”，提高代码可读性：

```c
// 在公共头文件（如 stm32f10x.h 或自定义的 utils.h）中定义
#define UNUSED(x) (void)(x)

// 在中断服务程序中使用
if (USART_GetITStatus(USART1, USART_IT_IDLE) != RESET) {
    uint32_t temp;  // 定义临时变量
    temp = USART1->SR;  // 读SR
    temp = USART1->DR;  // 读DR
    UNUSED(temp);  // 标记变量未使用，消除警告
}
```

- **原理**：`UNUSED(temp)` 本质也是 `(void)temp`，但通过宏名明确表达 “此变量未使用是故意的”，增强代码可维护性。
- **适用场景**：团队协作或需要明确注释的场景，让其他开发者理解 “变量存在的目的”。

## 3.直接合并读取操作

如果需要连续读取多个寄存器（如先读 SR 再读 DR），可将两个读取操作合并为一个表达式，避免单独定义变量：

```c
if (USART_GetITStatus(USART1, USART_IT_IDLE) != RESET) {
    // 合并读取操作，无需变量
    (void)(USART1->SR, USART1->DR);  // 逗号表达式，先执行SR读取，再执行DR读取
}
```

- **原理**：C 语言的逗号表达式会按顺序执行每个子表达式，并返回最后一个子表达式的结果，这里用 `(void)` 丢弃结果，同时完成两次读取。
- **注意**：确保寄存器读取的顺序正确（如必须先读 SR 再读 DR），逗号表达式会严格按顺序执行，符合硬件要求。

# 内存非对齐访问

## 1.如何查找与字节对齐方面的问题

如果出现对齐或者赋值问题首先查看：

1. 编译器的big little端设置；
2. 看这种体系本身是否支持非对齐访问；
3. 如果支持看设置了对齐与否,如果没有则看访问时需要加某些特殊的修饰来标志其特殊访问操作。

## 3.具体问题

### 1.考虑如下代码

```c++
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stddef.h>
#include <assert.h>

const int a[] = {0x98001f32};
typedef struct                                         //对应着 metering_task.xml 的配置

    unsigned char task_id;                             //集抄任务ID          子id：0x01
```

### 3.分析解释

#### 1.汇编指令

C++编译器会把fun函数翻译成汇编指令。

如**`fun(shor*)`**为：

```asm
000086dc <_Z3funPs>:
 	...
    86e8:	e1c030b0 	strh	r3, [r0]
    86ec:	e3a00001 	mov	r0, #1
    ...
```

**`fun(int*)`**为：

```asm
000086e8 <_Z3funPi>:
    ...
    870c:	e5842000 	str	r2, [r4] 
    8710:	e8bd4010 	pop	{r4, lr}
	...
```

**不写fun，直接在main函数为**：

```asm
000084dc <main>:
    ...
    8518:	e5cd5044 	strb	r5, [sp, #68]	; 0x44
    851c:	ebffffe8 	bl	84c4 <_init+0x50>
    8520:	e59f1084 	ldr	r1, [pc, #132]	; 85ac <main+0xd0>
    8524:	e5dd2040 	ldrb	r2, [sp, #64]	; 0x40
   ...
```

可以看到，编译器会根据传入的参数的类型，来把访存代码翻译为利用str或者strh或者strb的汇编语言，而在main函数中，无论何种类型变量，访存则利用strb。

#### 2.非对齐访问支持

ARMv7支持非对齐访问，虽然fun中传入的地址未对齐到4字节，且访存指令是str，但是ARMv7-A/R 架构引入了**非对齐访问硬件单元**，核心特性是自动拼接非对齐数据。当执行 `str r3, [r2]`（`r2` 指向非对齐地址，如 `0xbe91eb69`）时，硬件会自动拆分访问：

- 读取目标地址周围的两个对齐块（如 `0xbe91eb68~0xbe91eb6b` 和 `0xbe91eb6c~0xbe91eb6f`）。
- 替换其中对应非对齐地址的 4 字节数据（`0xbe91eb69~0xbe91eb6c`）。
- 合并后写回内存，**仅修改目标 4 字节，不影响相邻内存**（如 `0xbe91eb68` 的 `itemnum`）。

而ARM926EJ-S并不支持非对齐访问，所以当指针所指地址非对齐4字节，但仍然用str时会出现错误，且不报错。

## 4.解决办法

1. 让item成员地址对齐，取消packed属性。
2. 填充字节使该成员对齐。
