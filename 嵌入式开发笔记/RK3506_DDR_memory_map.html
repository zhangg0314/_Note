进入 board_init_f 前

crt0.S 先把 sp 放到配置给出的地址，再调用 board_init_f_alloc_reserve(top)。该函数从高到低预留早期 malloc 和 gd，返回 gd 起点；汇编随后把 sp 与 r9 都设为这个返回值。

SPL：top = 0x03F00000

  1. 0x03F00000原始栈顶同时是 SPL 镜像的起始边界；此时尚未分配 gd。
  2. 0x03E00000–0x03EFFFFF早期 malloc，1 MiBCONFIG_SPL_SYS_MALLOC_F_LEN 默认继承 CONFIG_SYS_MALLOC_F_LEN=0x100000。
  3. G_SPL–0x03DFFFFF临时 gd，向下按 16 字节对齐board_init_f_init_reserve 只把 gd 清零，并记录早期 malloc 起点。
  4. G_SPL 以下实际栈，继续向低地址增长栈长度不是由上述宏固定预留的。

G_SPL = align_down(0x03E00000 - sizeof(gd_t), 16)

U-Boot proper：top = 0x00600000

  1. 0x00600000原始栈顶来自 CONFIG_SYS_INIT_SP_ADDR。
  2. 0x00500000–0x005FFFFF早期 malloc，1 MiB来自 CONFIG_SYS_MALLOC_F_LEN=0x100000；不是后面的 16 MiB malloc。
  3. G_UB–0x004FFFFF临时 gd，向下按 16 字节对齐地址由本次编译的 sizeof(gd_t) 决定。
  4. G_UB 以下实际栈，继续向低地址增长board_init_f 在这套早期栈和 gd 上运行。

G_UB = align_down(0x00500000 - sizeof(gd_t), 16)

SPL 使用 Rockchip 自己的 board_init_f；普通 U-Boot 使用 common/board_f.c 的重定位预留序列。当前 defconfig 没有启用 CONFIG_SPL_STACK_R，因此 SPL 后续通常继续用原来的 gd 和栈。

  2. 02PRAM：默认 6 MiBCONFIG_PRAM=6144，单位 KiB；运行时环境变量 pram 可覆盖，接着向下对齐 4 KiB。
  3. 03MMU 页表：16 KiB，随后向下对齐 64 KiB当前 ARMv7 未启用 LPAE；若 I-cache 和 D-cache 都关闭，则跳过该预留。
  4. 04显示缓冲及 trace：按配置和运行时需求该 defconfig 启用了 DM_VIDEO，因此显示缓冲大小不能从这两个宏文件推定。
  5. 05重定位后的 U-Boot 镜像扣除 gd->mon_len = __bss_end - _start，再向下对齐 4 KiB；此地址成为 gd->relocaddr。
  6. 06正式 malloc 区扣除 TOTAL_MALLOC_LEN，通常以 CONFIG_SYS_MALLOC_LEN=16 MiB 为主体；与早期 1 MiB 区不同。
  7. 07非缓存内存：1 MiB，另有对齐空隙CONFIG_SYS_NONCACHED_MEMORY；ARMv7 非 LPAE 的对齐粒度为 1 MiB。
  8. 08bd_t、搬迁后的 gd_t、设备树及可选 bootstage这些区域继续从 gd->start_addr_sp 向低地址依次分配；设备树大小取决于实际 blob。
  9. 09最终栈顶先向下按 16 字节对齐；ARM 在 IRQ 关闭时再留 16 字节异常栈空间，启用 IRQ 时通常留 8192 字节。随后 crt0.S 切换到新 sp 和新 gd。

board_init_f_init_reserve 初始化的是最早的临时 gd；reserve_global_data 在重定位区另留一份，setup_reloc 才把临时 gd 复制过去。

精确的 sizeof(gd_t)、SPL BSS 实际结束地址、镜像长度和重定位地址，需要对应构建产物的 .config、map 文件，以及设备上 U-Boot 的 bdinfo 或启动日志。当前图采用所给 SDK 的 rk3506_defconfig 与 rk3506_common.h；TPL 不在本图分析范围内。
