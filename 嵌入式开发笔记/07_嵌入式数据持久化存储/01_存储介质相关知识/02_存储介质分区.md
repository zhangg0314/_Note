# 分区的概念意义

## 1.概念

分区是对 “非易失性存储” 的**逻辑切割**，就像把一个大仓库隔成多个小房间，每个房间放特定物品。即硬盘分区的意义在于更好地管理和组织数据。我们可以把硬盘想象成一个大仓库，而分区就像是在仓库内划出不同的区域。每个区域可以存放特定类型的物品，这样就更容易找到需要的东西。

## 2.硬盘分区

分区有以下几个好处：

1. **数据整理**
   通过分区，可以将不同类型的文件或数据分别存放在不同的区域中。比如，可以创建一个区域存放照片，另一个区域存放音乐，再一个区域存放工作文件。这样一来，可以更轻松地找到所需的文件，而不需要在整个硬盘上进行搜索。

2. **数据保护**
   分区可以将不同的数据隔离开来，这样即使一个区域的数据出现问题，其他区域的数据也可以保持安全。例如，如果操作系统发生故障需要重新安装，只需格式化操作系统所在的分区，其他分区中的数据将不受影响。

3. **多系统支持**
   分区还允许在同一硬盘上安装多个操作系统。可以将不同的操作系统安装在不同的分区上，每个操作系统都有自己独立的区域来存放文件和设置。这对于需要同时运行多个操作系统的朋友来说就非常有用。

4. **性能优化**

   通过合理的分区，可以提高硬盘的性能。比如，可以将常用的文件或程序放在一个分区中，将不常用的数据放在另一个分区中，这样在使用的过程中，就可以减少读写头的移动距离，提高文件的访问速度。

## 3.嵌入式分区

- **功能隔离**
  U-Boot（启动程序）和用户照片（数据）放在不同分区，即使照片被删，系统仍能启动。
- **技术限制**
  NAND Flash 有 “块擦除” 特性（擦除必须按块操作），分区可匹配块大小提高效率；部分文件系统（如 UBIFS）需要固定大小的分区。
- **安全性**
  给不同分区设置权限（如内核分区只读），防止误操作损坏关键文件。

## 4.核心差异

|    维度    |             电脑分区（如 Windows）              |                     嵌入式分区                     |
| :--------: | :---------------------------------------------: | :------------------------------------------------: |
|   灵活性   | 用户可随时用工具（如 `DiskGenius`）调整分区大小 | 分区大小和数量**固定**（由 U-Boot 或固件出厂定义） |
|    目的    |       方便用户管理（C 盘系统、D 盘文件）        |    满足系统启动和运行的技术需求（强制功能隔离）    |
| 分区表位置 |       存储介质的开头（MBR）或全局（GPT）        |        同电脑，但由 U-Boot 而非操作系统解析        |

# 分区表类型及命名

要让系统识别分区，需要 “分区表” 记录切割规则，以及 “命名规则” 标识每个分区。

## 1.分区表

分区表是存储在介质开头的**元数据**，包含每个分区的起始地址、大小、类型等信息。嵌入式常用两种分区表：

|           分区表类型            |       适用场景       |                           核心特点                           |                       嵌入式支持情况                        |
| :-----------------------------: | :------------------: | :----------------------------------------------------------: | :---------------------------------------------------------: |
|  **MBR（Master Boot Record）**  | 中小容量存储（<2TB） | 最多 4 个主分区，结构简单，兼容性好（所有 U-Boot 和内核都支持） |                最常用（90% 以上嵌入式设备）                 |
| **GPT（GUID Partition Table）** |  大容量存储（>2TB）  | 支持无限多个分区，支持分区名和 UUID（唯一标识），但老 U-Boot 可能不支持 | 高端设备（如 64GB 以上 eMMC）或需要多分区场景（如安卓设备） |

## 2.分区命名规则

Linux 内核会给每个分区分配一个 “设备文件名”，通过名字可判断分区来自哪种存储介质：

|    存储介质    |       设备文件命名规则       |                示例                | 含义解读                                                     |
| :------------: | :--------------------------: | :--------------------------------: | ------------------------------------------------------------ |
| NOR/NAND Flash | `/dev/mtdblockX`（X 是数字） | `/dev/mtdblock0`、`/dev/mtdblock1` | `mtd`代表 “Memory Technology Device”（Flash 专用驱动），`X`是分区序号（0 开始） |
|   eMMC/SD 卡   |       `/dev/mmcblkXpY`       | `/dev/mmcblk0p1`、`/dev/mmcblk1p2` | `mmcblk`代表 “MMC 块设备”，`X`是设备序号（0 是板载 eMMC，1 是插入的 SD 卡），`pY`是该设备的第 Y 个分区 |
| UBIFS 格式分区 |        `/dev/ubiX_Y`         |    `/dev/ubi0_0`、`/dev/ubi1_0`    | 针对 NAND 的 UBIFS 文件系统，`X`是 UBI 设备号，`Y`是卷号（类似分区） |
|    USB 设备    |         `/dev/sdXY`          |      `/dev/sda1`、`/dev/sdb2`      | 类似电脑 U 盘，`X`是设备序号（a 是第一个 USB 设备），`Y`是分区序号 |

**举例**：

- 看到 `/dev/mtdblock2` → 知道是 Flash 的第 3 个分区；
- 看到 `/dev/mmcblk0p3` → 知道是板载 eMMC 的第 4 个分区。

# MBR

MBR（Master Boot Record，主引导记录）是传统磁盘分区方案的核心数据结构，位于磁盘的第一个扇区（**0柱面0磁头1扇区**），负责引导操作系统和管理磁盘分区。以下从结构、功能、限制及实际应用进行全面解析。

## 1.物理结构与功能

MBR 的 512 字节划分非常严格，任何部分损坏都会导致无法启动或分区识别失败，具体结构如下：

| 偏移地址（十六进制） | 大小（字节） |            名称            |                           核心作用                           |
| :------------------: | :----------: | :------------------------: | :----------------------------------------------------------: |
|    0x000 - 0x1BD     |     446      | 引导程序（Bootstrap Code） | 嵌入式中通常是 U-Boot 的引导片段，PC 中是 GRUB 片段；功能是初始化硬件、找到内核分区并加载内核 |
|    0x1BE - 0x1FD     |      64      | 分区表（Partition Table）  | 记录最多 4 个主分区的信息（每个分区占 16 字节），是 MBR 的核心部分 |
|    0x1FE - 0x1FF     |      2       |   结束标志（Signature）    |  固定为`0x55AA`（魔数），系统通过这个标志判断 MBR 是否有效   |

**64 字节分区表（4 个主分区，每个 16 字节）**

每个主分区的 16 字节记录以下关键信息（决定分区能否被识别）：

1. **活动标志（1 字节）**：`0x80`表示该分区是 “启动分区”（系统从这里启动），`0x00`表示非启动分区；
2. **分区起始地址（3 字节）**：记录分区在存储介质上的物理起始位置（按柱面 - 磁头 - 扇区 CHS 格式）；
3. **分区类型（1 字节）**：标识分区的文件系统类型（如`0x83`=Linux ext4 分区，`0x0C`=FAT32 分区）；
4. **分区结束地址（3 字节）**：分区的物理结束位置（CHS 格式）；
5. **分区起始扇区（4 字节）**：LBA 格式的起始扇区（更精准的地址表示，替代 CHS）；
6. **分区总扇区数（4 字节）**：分区的总大小（扇区数 × 扇区大小 = 实际容量，扇区默认 512 字节）；
7. **预留（2 字节）**：未使用，固定为 0。

**举例**：一个 1GB 的 Linux 分区（ext4），其 16 字节分区表可能记录：

- 活动标志：`0x00`（非启动分区）；
- 分区类型：`0x83`（Linux 文件系统）；
- 总扇区数：`0x001F4000`（换算为 2097152 扇区 × 512 字节 = 1GB）。

## 2.MBR 的启动流程

以嵌入式 Linux 开发板（eMMC 存储，MBR 分区）为例，流程如下：

1. **上电初始化**
   开发板上电后，CPU 先执行硬件内置的 `BootROM` 程序（固化在芯片中）；
2. **读取 MBR**
   `BootROM` 自动读取 eMMC 的第 0 扇区（MBR），检查结束标志`0x55AA`是否有效（无效则启动失败）；
3. **执行引导程序**
   `BootROM` 将 MBR 中的 446 字节引导程序加载到内存并执行（嵌入式中这部分是 U-Boot 的精简版）；
4. **识别分区**
   引导程序解析 MBR 的 64 字节分区表，找到 “活动标志 = 0x80” 的启动分区（通常存 U-Boot 完整镜像或内核）；
5. **加载内核**
   引导程序从启动分区读取 Linux 内核和设备树（DTB）到内存，最终启动系统。

简单说：MBR 的引导程序是 “桥梁”，连接硬件 `BootROM` 和系统内核，而分区表是 “导航图”，告诉引导程序 “内核在哪里”。

## 3.主扩展与逻辑分区

MBR 的分区表只有 64 字节，最多只能记录 4 个主分区 —— 这是 MBR 最核心的限制。为了突破 “4 个分区” 的限制，MBR 引入了 “扩展分区 + 逻辑分区” 的机制：

1. **主分区（Primary Partition）**
   最多 4 个，可直接被系统识别和挂载，支持设置为启动分区；
2. **扩展分区（Extended Partition）**
   占用 1 个主分区名额，本身不能直接存储数据，而是作为 “容器” 容纳多个逻辑分区；
3. **逻辑分区（Logical Partition）**
   在扩展分区内创建，数量无限制（取决于存储容量），但不能设置为启动分区。

示例：MBR 分区方案（突破 4 个分区限制）

| 分区类型   | 数量 | 用途                      |
| ---------- | ---- | ------------------------- |
| 主分区 1   | 1 个 | 启动分区（存 U-Boot）     |
| 主分区 2   | 1 个 | 内核分区（存 Linux 内核） |
| 扩展分区   | 1 个 | 容器（容纳逻辑分区）      |
| 逻辑分区 1 | 1 个 | 根文件系统（`rootfs`）    |
| 逻辑分区 2 | 1 个 | 用户数据分区（`/data`）   |
| 逻辑分区 3 | 1 个 | 日志分区（`/var/log`）    |

**注意**：嵌入式系统中很少用扩展分区（因为分区数量通常≤4，且扩展分区会增加启动复杂度），多数嵌入式 MBR 直接用 4 个主分区满足需求（U-Boot、内核、根文件系统、用户数据）。

## 4.MBR 的局限性

- **容量限制**
  最大 2TB：分区表使用 32 位存储扇区地址，单个扇区 512 字节，理论容量为 2^32 × 512B = 2TB。
  超过 2TB 的磁盘：超出部分无法被寻址，需使用 GPT 分区表。

- **分区数量限制**
  最多 4 个主分区：若需更多分区，需将其中一个主分区设为 扩展分区，并在其内创建逻辑分区。逻辑分区依赖链式结构：扩展分区表以链表形式存储，易因某环节损坏导致全部分区丢失。

- **数据安全性**
  无冗余备份：MBR 仅存储于磁盘第一个扇区，损坏后需手动恢复。
  易受攻击：引导区病毒可篡改 MBR，导致系统无法启动。

## 5.嵌入式场景实际应用

### 1. 常见存储介质

  - **NAND/NOR Flash**
    嵌入式最常用，MBR 存于 Flash 的第 0 扇区，分区表记录 U-Boot、内核等分区；
  - **eMMC**
    板载 eMMC 的第 0 扇区为 MBR，分区表对应`mmcblk0p1`（U-Boot）、`mmcblk0p2`（内核）等；
  - **SD 卡**
    开发阶段用 SD 卡调试时，SD 卡的第 0 扇区为 MBR，分区表记录系统各组件。

  ### 2.修改与维护

# GPT

GPT（GUID Partition Table，全局唯一标识分区表）是为突破 MBR 限制而设计的现代分区表格式，支持大容量存储、无限分区数量，且具备更强的可靠性。在嵌入式 Linux 中，随着 eMMC/SD 卡容量提升（如 64GB 以上），GPT 逐渐成为主流。下面从结构、特性、工作流程到嵌入式应用，全面解析 GPT：

## 1.GPT 的核心定位

GPT 是 UEFI 规范（替代传统 BIOS）的一部分，最初为 PC 设计，后被嵌入式系统采纳。它解决了 MBR 的三大痛点：

- 容量限制（MBR 最大 2TB，GPT 支持至 PB 级）；
- 分区数量限制（MBR 最多 4 主分区，GPT 无限制）；
- 可靠性不足（MBR 无备份，GPT 自动备份分区表）。

在嵌入式中，GPT 主要用于 **大容量 eMMC/SD 卡**（如 64GB+）或需要 **多分区管理** 的场景（如安卓设备、工业控制设备）。

## 2.GPT 的结构

GPT 不再局限于 MBR 的 512 字节，而是在存储介质的**开头和结尾**都存储数据，总结构如下（以 512 字节扇区为例）：

|      位置      | 大小（扇区） |                名称                 |                           核心作用                           |
| :------------: | :----------: | :---------------------------------: | :----------------------------------------------------------: |
|   第 0 扇区    |      1       |     保护 MBR（Protective MBR）      | 兼容不支持 GPT 的老系统，假装是 MBR 分区表（标记整个设备为 “GPT 保护分区”，防止误操作） |
|   第 1 扇区    |      1       |         GPT 表头（Header）          | 记录 GPT 分区表的位置、大小、校验和、分区数量上限（默认 128）、备份表头位置等元数据 |
| 第 2 - 33 扇区 |      32      |    分区表项（Partition Entries）    | 每个分区占 128 字节，默认支持 128 个分区（32 扇区 × 512 字节 / 扇区 ÷ 128 字节 / 分区 = 128 分区） |
|    中间区域    |      -       |            实际分区数据             |      存储文件系统和数据（如 U-Boot、内核、根文件系统）       |
|  最后 34 扇区  |      34      | 备份 GPT（Backup Header + Entries） | 表头和分区表的完整备份，当主 GPT 损坏时可恢复（嵌入式中部分设备可能省略，但规范要求必须有） |

**关键：128 字节的分区表项**

GPT 每个分区的信息记录比 MBR 详细得多，包含：

1. **分区类型 GUID**
   全球唯一的类型标识（如 `0FC63DAF-8483-4772-8E79-3D69D8477DE4` 代表 Linux 文件系统分区，`C12A7328-F81F-11D2-BA4B-00A0C93EC93B` 代表 EFI 系统分区）；
2. **分区唯一 GUID**
   每个分区的唯一标识（类似 UUID，用于精准定位分区，避免设备名变化导致挂载失败）；
3. **起始 / 结束 LBA 地址**
   分区在存储介质上的精确位置（LBA 是逻辑块地址，1 块 = 512 字节或 4096 字节，支持大容量）；
4. **分区名称**
   支持 Unicode 字符（如 `boot` `rootfs` `userdata`，直接显示分区用途）；
5. **属性标志**
   如 “只读”、“隐藏”、“启动分区” 等（嵌入式中常用 “启动分区” 标志指定内核位置）。

## 3.GPT 的工作流程

以支持 UEFI 的嵌入式开发板（大容量 eMMC，GPT 分区）为例，启动流程如下：

1. **上电初始化**
   CPU 执行 `BootROM`（支持 GPT），读取存储介质第 0 扇区（保护 MBR），发现是 GPT 格式后跳过；
2. **读取 GPT 表头**
   `BootROM `读取第 1 扇区的 GPT 表头，验证校验和（确保未损坏），获取分区表项的位置和数量；
3. **解析分区表**
   读取第 2 - 33 扇区的分区表项，根据 “分区类型 GUID” 或 “分区名称” 找到启动相关分区（如 EFI 系统分区或 U-Boot 分区）；
4. **加载启动程序**
   从启动分区读取 U-Boot 或内核到内存，执行启动逻辑；
5. **内核挂载分区**
   内核启动后，通过分区的 “唯一 GUID” 或 “名称” 挂载根文件系统（如 `root=PARTUUID=xxx`），不依赖设备名（如 `mmcblk0p3`），更稳定。

## 4.GPT 的核心特性

### 1. 突破容量限制

GPT 用 64 位表示 LBA 地址，若扇区大小为 512 字节，最大支持容量 = 2⁶⁴ × 512 字节 ≈ 8ZB（zettabyte，1ZB = 10 亿 TB），完全满足嵌入式大容量存储（如 128GB、512GB eMMC）需求。

### 2. 无限分区数量

默认支持 128 个分区（可通过 GPT 表头调整），无需 MBR 的 “扩展分区 + 逻辑分区” 复杂机制，直接创建多个主分区（如 U-Boot、内核、DTB、`rootfs`、用户数据、日志、缓存等），管理更清晰。

### 3. 高可靠性

- **双重备份**
  主 GPT（开头）和备份 GPT（结尾）完全一致，主分区表损坏时可通过备份恢复；
- **校验和机制**
  表头和分区表项都有 CRC32 校验和，系统启动时自动检查，发现损坏会报错；
- **保护 MBR**
  兼容不支持 GPT 的老工具（如老版本 `fdisk`），防止误格式化整个设备。

### 4. 灵活的分区标识

- 支持 **分区名称**（如 “kernel_a”、“kernel_b”，方便双系统切换）
- 支持 **唯一 GUID**（替代 MBR 的设备名），内核挂载时用 `PARTUUID=xxx` 或 `PARTLABEL=xxx`，避免设备名变化（如插入 USB 后 eMMC 设备名从 `mmcblk0` 变为 `mmcblk1`）导致的挂载失败。

## 5.GPT 的实际应用

### 1. 适用设备与存储介质

- **大容量 eMMC**
  64GB 以上的开发板（如树莓派 4B、全志 H616 开发板）；
- **多分区需求设备**
  安卓开发板（需 boot、system、vendor、data 等多个分区）、工业设备（需日志、配置、固件分区分离）；
- **UEFI 兼容设备**
  支持 UEFI 启动的嵌入式芯片（如 Intel Atom、NXP i.MX8）。

### 2. 分区的创建与管理

- U-Boot 中操作（需开启`CONFIG_PARTITION_TYPE_GPT`配置）：

  ```bash
  gpt write mmc 0  # 初始化 eMMC（mmc 0）为 GPT 分区表
  gpt add mmc 0 0x200000 0x1000000 "kernel" 0FC63DAF-8483-4772-8E79-3D69D8477DE4  # 添加 256MB 内核分区

- Linux 系统中操作：

  ```bash
  parted /dev/mmcblk0  # 进入 eMMC 的 GPT 分区编辑模式
  (parted) mklabel gpt  # 初始化 GPT 分区表
  (parted) mkpart kernel ext4 100MB 500MB  # 创建 100MB-500MB 的内核分区（ext4 格式）
  (parted) name 1 kernel  # 给第 1 个分区命名为“kernel”
  ```

- 查看 GPT 分区信息：

  ```bash
  fdisk -l /dev/mmcblk0  # 显示分区表类型为 gpt，及各分区的 GUID、名称
  blkid  # 查看各分区的 PARTUUID（唯一 GUID）和 PARTLABEL（名称）
  ```

### 3. 烧录与启动配置

- **烧录镜像到 GPT 分区**
  直接指定分区设备名（如 `dd if=kernel.img of=/dev/mmcblk0p2`），或用分区名（需工具支持）；

- **内核启动参数**
  通过分区唯一 GUID 或名称挂载根文件系统，更稳定：

  ```bash
  # 用分区名称（PARTLABEL）
  bootargs=console=ttyS0 root=PARTLABEL=rootfs rw
  
  # 用分区唯一 GUID（PARTUUID）
  bootargs=console=ttyS0 root=PARTUUID=12345678-1234-5678-1234-567812345678 rw
  ```

  

# GPT 与 MBR 的对比

|      维度      |              MBR              |                  GPT                  |             嵌入式建议              |
| :------------: | :---------------------------: | :-----------------------------------: | :---------------------------------: |
|    最大容量    |              2TB              |            8ZB（几乎无限）            |    ≤2TB 用 MBR，>2TB 必须用 GPT     |
|    分区数量    | 最多 4 主分区（扩展分区复杂） |          默认 128 个，可扩展          |     分区数 ≤4 用 MBR，>4 用 GPT     |
|     兼容性     |    所有 U-Boot / 内核支持     | 仅支持较新 U-Boot（需开启配置）和内核 |    老旧设备用 MBR，新设备用 GPT     |
|     可靠性     |   无备份，损坏后分区表丢失    |    双重备份 + 校验和，抗损坏能力强    |  数据重要场景（如工业设备）用 GPT   |
|    启动速度    |    解析快（512 字节结构）     |   解析稍慢（需读取表头和分区表项）    | 对启动速度敏感用 MBR（如 IoT 设备） |
| 分区标识灵活性 |  仅设备名（如 `mmcblk0p1`）   |          支持名称和唯一 GUID          |       需要动态识别分区用 GPT        |



# MTD 固定分区表

### 1.体系核心

MBR 体系的本质不是 “主分区 / 扩展分区”，而是 **“通过固定的分区表记录每个分区的起始地址、大小、名称，系统启动时按表解析”**—— 这是 MBR 最核心的逻辑。

而MTD固定分区完全符合这个核心：

- 分区表是 “固定的”（写在设备树或 U-Boot 的 `mtdparts` 中，不动态变化）；
- 每个分区的起始地址、大小都是预先定义的（比如 `mtd0` 起始 0x0、大小 256KB，`mtd1` 紧跟其后）；
- 系统启动时，内核按分区表直接创建分区（无需复杂解析）。

所以说它属于 MBR 体系，是因为 “分区表的设计逻辑” 和 MBR 一致，而非 “完全照搬机械硬盘的主 / 扩展分区机制”。

### 2.无主扩展分区

“主分区 / 扩展分区” 是 MBR 为 **机械硬盘** 设计的 “妥协方案”—— 因为机械硬盘的 MBR 分区表只有 64 字节，最多只能记录 4 个分区信息，才不得不引入 “扩展分区” 作为容器，容纳更多逻辑分区。

但MTD 的设备是 **NAND Flash**，用的是 MTD 子系统的 `ofpart` 分区驱动，它解决了 MBR 的原始限制：

1. 分区表不局限于 64 字节（设备树或 `mtdparts` 可以定义任意多个分区）；
2. 无需 “扩展分区” 当容器 —— 直接按功能顺序划分 12 个独立分区，每个分区都是 “等价的”（没有主 / 扩展之分）；
3. 适配 Flash 的物理特性（比如分区大小是擦除块的整数倍），而非机械硬盘的柱面 / 磁头结构。

简单说：嵌入式工程师拿了 MBR “固定分区表” 的核心逻辑，去掉了机械硬盘的 “4 分区限制” 和 “主 / 扩展分区” 冗余设计，改成了更适合 Flash 的 “直连式多分区”。

### 3.关键区别表

|    对比维度    |           机械硬盘的标准 MBR           |    你的设备（MBR 体系的嵌入式变种）    |
| :------------: | :------------------------------------: | :------------------------------------: |
|    核心逻辑    |   固定分区表（记录起始地址 / 大小）    |      固定分区表（同上，继承核心）      |
|  分区数量限制  | 最多 4 主分区（需扩展分区 + 逻辑分区） |      无限制（直接定义 12 个分区）      |
|    分区关系    |  主分区 → 扩展分区 → 逻辑分区（层级）  | 所有分区平级（无主 / 扩展 / 逻辑之分） |
|    适配介质    |          机械硬盘 / 固态硬盘           |       NAND/NOR Flash（MTD 设备）       |
| 分区表存储位置 |       介质第 0 扇区（512 字节）        | 设备树或 U-Boot 环境变量（`mtdparts`） |

### 4.最终结论

可以理解为：MTD是 “MBR 的简化增强版”—— 保留了 MBR 稳定、简单的核心优势，去掉了为老硬件设计的 “主 / 扩展分区” 限制，更适合嵌入式 Flash 设备。所以不用纠结 “哪个是主分区 / 扩展分区”，各个分区都是 “平级的独立功能分区”，按命名和功能操作（比如 `mtd1` 是 U-Boot、`mtd6` 是内核）即可，这就是嵌入式 MTD 分区的标准用法～
