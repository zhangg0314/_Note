# 与加密认证的关系

加密（Encryption）和认证（Authentication）依赖对称密钥，通信双方共享同一密钥。由此产生一个固有局限：无法区分消息由哪一方生成——双方均持有相同密钥，均能产生合法的加密密文和认证标签。

**ECDSA（Elliptic Curve Digital Signature Algorithm）** 解决这一局限。它使用非对称密钥，引入**不可否认性（Non-Repudiation）**。

| 保护机制 | 密钥类型 | 核心能力 | 不可否认性 |
| :--: | :--: | :--: | :---: |
| 加密（AES-CTR） | 对称密钥 | 机密性——防止窃听 | ❌ |
| 认证（GMAC） | 对称密钥 | 完整性 + 真实性——防止篡改与冒充 | ❌ |
| 数字签名（ECDSA） | 非对称密钥（私钥） | 完整性 + 真实性 + **不可否认** | ✅ |

不可否认性的技术本质：签名私钥仅签名方持有，公钥公开可验。任何人用公钥验证通过即表明签名必定由私钥持有者生成，签名方事后无法否认。

# DLMS 中的应用场景

## 1.HLS 强身份验证

DLMS 高层安全认证机制中，机制 7 以 ECDSA 替代 GMAC 对称认证：

```
客户端 ←── Challenge ──→ 电表
客户端 ←── ECDSA_Sign(Challenge + 附加信息, 私钥) ──→ 电表
电表以客户端公钥证书验证签名 → 确认客户端身份
```

优势：无需预先共享对称密钥。电表预置客户端公钥证书即可完成身份验证。

### 2.2 固件签名验证

DLMS 的 Active Firmware Signature 对象存储固件镜像的数字签名：

```
厂商以私钥签署固件镜像 → 固件 + 签名一并分发
电表以厂商公钥证书验证签名 → 确认固件来源可信且未被篡改
```

### 2.3 证书链信任传递

PKI 体系中，各级证书均以上级 CA 的 ECDSA 签名完成信任传递：

```
Root-CA 私钥 ──签名──→ Sub-CA 证书
Sub-CA 私钥 ──签名──→ 终端实体证书（含设备公钥）
```

验证方只需信任根证书，即可沿证书链逐级验证，最终信任未曾直接接触的终端设备。这是新设备入网与多厂商互通的基础。

### 2.4 xDLMS APDU 数字签名

Security Policy 中，数字签名作为独立控制位，可对每条请求/响应单独启用：

```
Bit 2: authenticated request
Bit 3: encrypted request
Bit 4: digitally signed request      ← ECDSA，独立控制
Bit 5: authenticated response
Bit 6: encrypted response
Bit 7: digitally signed response     ← ECDSA，独立控制
```

# 数学原理

## 1. 数学基础

ECDSA 的安全性建立于椭圆曲线离散对数难题（ECDLP）的单向性之上。DLMS 采用 NIST 标准曲线 **P-256**（secp256r1），对应 FIPS PUB 186-4 规范。

### 1.密钥对生成

```
公钥 Q = d × G    （在 P-256 曲线上）
```

- `d` — 私钥，在区间 [1, n-1] 内随机生成，n 为基点 G 的阶，约 2²⁵⁶。因此 d 为 **256 位（32 字节）** 的整数，约 10⁷⁷ 量级。仅持有者知晓
- `G` — 基点，P-256 曲线上固定公开点，**坐标由 NIST 标准定义**
- `×` — 椭圆曲线标量乘法（即重复点加法：G + G + … + G，共 d 次）
- `Q` — 公钥，P-256 曲线上一点，公开发布

### 2.单向性

- 已知 d 和 G，计算 Q 仅需数百次点运算（容易）
- 已知 Q 和 G，反推 d 等价于求解 P-256 上的椭圆曲线离散对数问题（ECDLP），搜索空间约 2²⁵⁶，目前数学上无多项式时间算法，计算上不可行

##  2.签名过程

输入：消息 M，私钥 d

```
1. 计算消息哈希    z = SHA(M)
2. 生成随机数      k（一次性使用，不可重复）
3. 计算凭证点      P = k × G
4. 取凭证坐标      r = P.x（P 的横坐标）
5. 绑定消息与私钥  s = k⁻¹ × (z + d × r)  mod n
6. 输出签名        (r, s)
```

关键点：
- k 必须随机且一次性使用——两个不同消息使用同一 k 会导致私钥被推导
- k⁻¹ 为 k 在模 n 下的乘法逆元
- s 将消息 z、私钥 d、凭证 r 绑定为一体

## 3.验证过程

输入：消息 M'，签名 (r, s)，公钥 Q

```
1. 计算消息哈希    z = SHA(M')
2. 重构凭证点      P' = s⁻¹ × z × G + s⁻¹ × r × Q
3. 比对横坐标      P'.x == r ?
                     ✅ 相等 → 签名有效
                     ❌ 不等 → 签名无效
```

## 4.验证公式的推导

验证公式有效，因为签名与验证是一对互为逆运算的配对构造：

```
验证公式:
  P' = s⁻¹ × z × G + s⁻¹ × r × Q

代入公钥定义 Q = d × G:
  P' = s⁻¹ × z × G + s⁻¹ × r × d × G
     = s⁻¹ × (z + r × d) × G          ← 提取公因子

代入签名公式 s = k⁻¹ × (z + d × r):
  s⁻¹ × (z + d × r) = k                ← 两边取逆

代入上式:
  P' = k × G = P

故 P'.x = P.x = r  ✅
```

验证通过的前提：签名确实使用与 Q 对应的私钥 d 生成。任何伪造签名均无法使等式成立。

# 从 ElGamal 到 ECDSA

ECDSA 公式并非凭空构造，而是从目标约束倒推设计的结果。

## 1.历史渊源

ECDSA 是 **`ElGamal` 签名方案（1985）** 的椭圆曲线移植版本。`ElGamal`原方案在有限域的乘法群上定义——使用模幂运算。迁移至椭圆曲线时面临关键差异：椭圆曲线仅有点加法一种运算。

## 2.构造逻辑（倒推法）

设计者的推理链条：

```
目标：     验证方能够计算出点 P = k × G（因为 r 定义为 P 的横坐标）

约束：     验证方仅持有公钥 Q = d × G，只能执行椭圆曲线点乘和点加

构造：     验证方能够计算的最一般形式：
               P' = a × G + b × Q          （a, b 为待定系数）

代入 Q：    P' = a × G + b × d × G = (a + b·d) × G

要求等于：  k × G
              ⇒ a + b·d = k

选取系数：  验证方能从 (r, s, z) 计算出 a 和 b
            最简洁的选择：a = s⁻¹·z，b = s⁻¹·r

代入约束：  s⁻¹·z + s⁻¹·r·d = k
              ⇒ s⁻¹·(z + r·d) = k
              ⇒ s = k⁻¹·(z + r·d)          ← 签名公式由此导出
```

验证公式即系数选取步骤的直接体现：

```
P' = s⁻¹ × z × G + s⁻¹ × r × Q
```

**签名公式与验证公式是同时推导的配对公式**——并非先有签名公式再构造验证公式，而是两者在约束条件下共同确定。

## 3. 安全性基础的三要素

公式构造满足以下三项安全需求：

| 需求 | 含义 | 实现保证 |
| :--: | :--: | :--: |
| **可验证性** | 验证方用公钥 Q 可确认签名由对应私钥 d 生成 | 验证等式 P'.x = r 当且仅当使用正确私钥时成立 |
| **不可伪造性** | 无私钥者即使知道公钥 Q 也无法构造合法签名 | 由 ECDLP 保证，无法从公钥反推私钥 |
| **不可重用性** | 同一条消息的两次签名必须互不相同 | 随机数 k 每次独立生成，确保 (r, s) 不重复 |

# 本章总结

ECDSA 的核心价值在于**不可否认性**——解决了对称密钥体系中"无法证明消息由谁生成"的根本局限。

在 DLMS 体系中，ECDSA 服务于四个关键场景：
- HLS 强身份验证（机制 7）
- 固件镜像签名验证
- PKI 证书链信任传递
- APDU 级数字签名

其数学基础是椭圆曲线离散对数难题（ECDLP）的单向性，签名与验证公式从 ElGamal 方案演化而来，通过倒推法构造为一对互为逆运算的配对公式。理解 ECDSA 的关键在于把握：私钥生成签名、公钥验证签名、从公钥反推私钥在计算上不可行——三者共同构成数字签名的安全基础。
