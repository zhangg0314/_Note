# 基础构建工具

## autoconf 2.69（源码编译）

仓库里 autoconf 包被 autoconf2.64 替代，`apt-get install autoconf=2.69` 找不到。从源码装：

```bash
wget -P /tmp https://ftp.gnu.org/gnu/autoconf/autoconf-2.69.tar.gz
cd /tmp && tar -xzf autoconf-2.69.tar.gz && cd autoconf-2.69
./configure --prefix=/usr/local
make -j$(nproc)
sudo make install

# 验证
autoconf --version
```

### debhelper / autotools-dev

源码编译太麻烦，直接用 apt 仓库版本：

```bash
sudo apt-get install debhelper autotools-dev
```

> 如需指定版本：先 `apt-cache policy debhelper autotools-dev` 查可用版本，再 `sudo apt-get install debhelper=<版本> autotools-dev=<版本>`。

## 2. ARM 交叉工具链

gcc-linaro-7.4.1-2019.02-x

### 现用版本（有问题）

`/opt/gcc-linaro-5.3.1-2016.05-x86_64_arm-linux-gnueabihf/`

- GCC 5.3.1，C++14 支持不完整
- `std::hash<enum class>` 自动特化没实现，编译报错：
  ```
  error: no match for call to '(const std::hash<BusinessErrno>) (const BusinessErrno&)'
  ```

### 升级方案：Linaro GCC 7.5.0（2019.12）

GCC 7 解决 C++14 哈希特化问题，且前缀不变（`arm-linux-gnueabihf-`），Makefile 不用改：

```bash
# 下载
wget -P /tmp https://releases.linaro.org/components/toolchain/binaries/latest-7/arm-linux-gnueabihf/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabihf.tar.xz

# 解压到 /opt
sudo tar -xf /tmp/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabihf.tar.xz -C /opt/

# 配环境变量
echo 'export PATH=/opt/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabihf/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# 验证
arm-linux-gnueabihf-gcc --version
# 应输出: arm-linux-gnueabihf-gcc (Linaro GCC 7.5-2019.12) 7.5.0
```

> **备选：ARM 官方 GNU Toolchain 13.2** — GCC 13，但前缀变成 `arm-none-linux-gnueabihf-`，Makefile 需改 `CROSS_COMPILE`。
> 下载页：https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads
> 老 ARM 官网链接常 404，需手动浏览器下载。

## 3. 常见问题

### GCC 5 下 std::hash<enum class> 报错

编译器太老。GCC 5 的 C++14 支持不完整，`std::hash` 对 `enum class` 的自动特化没实现。

**选 1：升级编译器（推荐）**
见上方「ARM 交叉工具链 → 升级方案」。

**选 2：不改编译器，代码里补 hash 特化**
在 `HttpApiError.hpp`（或 `BusinessErrno` 定义文件）里加：

```cpp
namespace std {
    template<>
    struct hash<BusinessErrno> {
        size_t operator()(const BusinessErrno& e) const noexcept {
            return hash<int>{}(static_cast<int>(e));
        }
    };
}
```

### g++-7 找不到（Ubuntu 16.04）

Ubuntu 16.04 默认源没有 g++-7。加 PPA：

```bash
sudo add-apt-repository ppa:ubuntu-toolchain-r/test
sudo apt-get update
sudo apt-get install g++-7
```

或者用 `dpkg-buildpackage` 编译时指定自带编译器：

```bash
CXX=g++-7 CC=gcc-7 dpkg-buildpackage -us -uc
```

### 锁定包版本防止自动升级

```bash
sudo apt-mark hold autoconf automake libtool debhelper autotools-dev
```

### sqlite3：从开发板拷贝 + 创建软连接

工具链 7.4.1 自带 libsqlite3，但编译机上可能只拷了文件没软链。从板子 scp：

```bash
# 在编译机上执行
BOARD_IP=<板子IP>

# 库文件
scp -r root@${BOARD_IP}:/opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/lib/libsqlite3.* \
    /opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/lib/

# 头文件
scp root@${BOARD_IP}:/opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/include/sqlite3.h \
    /opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/include/
```

scp 不通就用 tar 中转（板子上打，USB/网络传到编译机）:

```bash
# 板子
cd /opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf
tar -czf /tmp/sqlite3-arm.tar.gz lib/libsqlite3.* include/sqlite3.h

# 编译机
sudo tar -xzf sqlite3-arm.tar.gz -C /opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/
```

---

创建软连接（scp/tar 可能丢失软链，需手动重建）:

```bash
cd /opt/gcc-linaro-7.4.1-2019.02-x86_64_arm-linux-gnueabihf/arm-linux-gnueabihf/lib

sudo ln -sf libsqlite3.so.0.8.6 libsqlite3.so.0
sudo ln -sf libsqlite3.so.0.8.6 libsqlite3.so
```

> `ln -s <目标> <链接名>` 创建软连接，`-sf` 覆盖已存在的。软链恢复后 `libsqlite3.so -> libsqlite3.so.0 -> libsqlite3.so.0.8.6`。
