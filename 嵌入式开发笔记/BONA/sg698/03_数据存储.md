

# `paramshm`

## 1.`creatDB`

此目录的功能主要是将`format45.xml`的内容转为`fornat45.db`GDBM数据库格式。其内容主要是各个参数的名字标识，以及改参数有哪些子参数，各个子参数的类型，以及自身及其子参数的内容存储在哪个XML文件中。

**数据结构**如下：

```c++
typedef struct{
	int SubTypeID; 	//次标识ID
	char strSubType[MAX_TYPE_NAME_LEN];		//次标识字符串
	unsigned short Position;  	//位置，因为所有子项的内容都被看成一串连在一起的字节串，因此需要pos位置划分界限
	int Length;		//长度
	int FuncID;		//转换函数ID
} __attribute__((packed)) S_SUB_ITEM;

typedef struct{
	int MainTypeID;	//  主标识ID
	char strMainType[MAX_TYPE_NAME_LEN]; 		//  主标识字符串
	char strFilePath[MAX_PARAM_FILE_PATH_LEN]; 		//  参数所在文件的字符串
	bool IsMulti;       		//  本块参数需查询多测量点（或总加组等）
	int ItemNum;		//次标识数量 
	S_SUB_ITEM *ps_Item;    	//  每一子项参数
} __attribute__((packed)) S_MAIN_ITEM;
```

## 2.`db2xml`

由于`GDBM`数据库不像`sqlite`那样直接用相关可视化软件或者命令行敲击查看，因此此目录的功能主要是将各个存储在`GDBM`数据库中的数据的内容转为XML格式。方便我们观察各个参数存的到底是什么值。

- 正转

# 旧数据库（dblite）

## 1.介绍

`dblite`目录是由`Sqlite3`来实现的数据库接口，采用多态的方式定义了多个数据库接口。比如存`DLMS`参数的数据库，存`DLMS`抄表记录的数据库、存集中器事件的数据库等，即一个`.db`数据库文件存一种大类的数据，然后一个大类又分很多类，即一个`.db`文件里又有很多表table，比如抄读表的数据存在同一个`.db`数据库中，但表的数据有冻结数据，事件等，所有冻结数据和事件又各自开一张表table，这样分的细。旧数据库最早寸的是698相关的，后面海外需求新增了`DLMS`。

## 2.结构介绍

文件位置：`DBLiteInterface.h、DBLiteInterface.cpp`
