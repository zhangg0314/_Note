## 2.架构核心组

1. **调度线程（生产者 T1/T2/T3）**
   1 个线程绑定 1 个优先级队列，仅负责**对应队列的任务入队**/**任务元信息封装**/**队列状态维护**，无跨队列操作，不与其他调度线程交互；
2. **优先级任务队列（Q1/Q2/Q3）**
   3 个独立的**线程安全队列**，分别存储高 / 中 / 低优先级任务，是生产者与消费者的唯一数据交互载体；
3. **工作通道（消费者 C1-C10）**
   10 个独立 `MeterChannel`，1:1 绑定工作线程，核心逻辑为 **「循环探询队列→按优先级取任务→执行任务→完成后继续探询」**，通道间完全隔离，无任何共享资源；
4. **物理设备层**
   实际的智能电表、串口 / 网口采集通道，由工作通道独占式访问，与通道一一对应。

## 4.互斥 / 同步核心规则

1. **生产者 - 队列互斥**
   调度线程 T1→Q1、T2→Q2、T3→Q3 的**入队操作**，与工作线程 C1-C10→对应队列的**出队操作**互斥，由队列专属锁 M1/M2/M3 保证原子性；
2. **消费者 - 队列互斥**
   10 个工作线程对同一队列的**出队 / 判空操作**互斥（如 C1 和 C2 同时访问 Q1，需竞争锁 M1），不同队列的锁完全独立，无竞争；
3. **无消费者间同步**
   C1-C10 之间无任何箭头 / 交互，通道独立，无共享资源，无需互斥 / 同步；
4. **无生产者间同步**
   T1-T3 之间无任何箭头 / 交互，各管一个队列，队列锁独立，无需互斥 / 同步；
5. **优先级探询规则**
   所有工作线程均遵循 **「Q1 优先→Q2 次之→Q3 最后」** 的探询顺序，由工作线程本地逻辑保证，无全局调度干预。

## 三、互斥同步设计核心分析（无调度器版）

### 1. 核心互斥：队列级专属锁（M1/M2/M3）

- **锁粒度**：**队列级细粒度锁**，3 个队列各一个独立的互斥锁，无全局锁，最大程度降低锁竞争；
- **锁保护范围**：单个队列的**所有操作**（入队、出队、判空、获取队列长度），保证队列自身的线程安全；
- **竞争场景**：仅「多个工作线程同时访问同一队列」「调度线程与工作线程同时访问同一队列」两种竞争场景，无额外无效竞争；
- **非竞争场景**：工作线程访问不同队列、调度线程访问各自队列、工作线程执行任务，均无锁竞争，并发效率最大化。

### 2. 无全局同步：工作线程自主探询，避免中心依赖

去掉调度器后，无「调度器 - 工作线程」的双向同步，工作线程采用 **「循环探询 + 空队列短休眠」** 逻辑，核心优势：

- **无中心单点故障**：无需依赖调度器的分发逻辑，单个工作线程 / 队列故障，不影响其他组件运行；
- **无同步等待开销**：工作线程无需等待调度器的通知信号（条件变量），探询到任务即执行，减少线程唤醒 / 阻塞的系统开销；
- **适配嵌入式场景**：逻辑简单、无复杂同步原语，适合资源受限的嵌入式 Linux 环境（智能电表集中器典型场景）。

### 3. 优先级保障：工作线程本地硬编码探询顺序

优先级的严格性由**所有工作线程统一遵循「Q1→Q2→Q3」的探询顺序**保证，是无调度器方案的核心优先级实现方式：

- **严格高优优先**：工作线程每次探询均先检查 Q1，仅当 Q1 无任务时才会检查 Q2，Q2 无任务时才会检查 Q3，从消费侧保证高优先级任务被优先获取；
- **无优先级抢占**：若工作线程已获取 Q2/Q3 任务并执行，即使 Q1 有新任务入队，也需等该线程完成当前任务后，才会重新探询 Q1（非抢占式，符合工业设备任务执行的原子性要求）；
- **天然负载均衡**：10 个工作线程同时探询队列，高优先级队列的任务会被所有线程快速抢取执行，无需调度器分发，天然实现消费侧负载均衡。

## 四、低优先级任务防饥饿设计（无调度器版）

无调度器时，若高优先级 Q1 任务持续入队，工作线程会一直探询 Q1，导致 Q2/Q3 任务长期无法执行，需在**工作线程探询逻辑**中增加**轻量级防饥饿策略**，无需额外组件，仅本地逻辑实现：

### 策略 1：探询次数阈值兜底

工作线程连续探询 Q1 并获取任务的次数达到阈值（如 10 次）后，**强制跳过 Q1 一次**，依次探询 Q2/Q3，给低优先级队列一次被访问的机会；

### 策略 2：队列等待时间兜底

工作线程探询 Q1 时，若检测到 Q2/Q3 有任务且等待时间超过阈值（如 30s），**临时调整探询顺序**，优先探询超时的低优先级队列；

### 策略 3：空闲时间窗口兜底

若工作线程获取 Q1 任务后，队列 Q1 变为空，**在下次探询前增加短时间休眠（如 10ms）**，给 Q2/Q3 任务留出被探询的时间窗口。

以上策略均由工作线程**本地独立执行**，无跨线程同步，不增加架构复杂度，适配无调度器的设计初衷。

## 五、架构核心优势（无调度器版）

### 1. 极致简洁，适配嵌入式 / 工业场景

去掉中心调度器，减少一层组件依赖，架构逻辑简单、部署成本低，适合智能电表集中器等**资源受限的嵌入式 Linux 环境**，降低系统崩溃风险；

### 2. 并发效率更高，锁竞争最小化

队列级细粒度锁 + 无全局同步 + 无中心调度器，避免了调度器与工作线程的同步开销、调度器的全局锁竞争，10 个消费者 + 3 个生产者可实现高效并发；

### 3. 高可用，无单点故障

无中心调度器，任何一个组件（调度线程、工作线程、队列）故障，均不会影响其他组件的正常运行，架构鲁棒性更强；

### 4. 完全兼容原有 MeterChannel 设计

保留你核心的 **「1 个线程管理 1 个 MeterChannel」** 设计，MeterChannel 内部成员仅由自身工作线程访问，无需额外互斥，直接复用原有代码；

### 5. 易扩展，灵活调整组件数量

可按需灵活增加 / 减少工作通道数（如从 10 个扩为 20 个）、新增优先级队列（如新增超高优先级 Q0），仅需新增队列 / 通道，无需修改原有组件逻辑。

## 六、架构适用场景与边界

### 适用场景（完美匹配智能电表采集业务）

1. 工业设备采集场景：任务执行具有**原子性**（不可抢占）、**低延迟**（高优先级任务需快速响应）；
2. 资源受限环境：嵌入式 Linux / 单片机，对系统资源（内存、CPU）占用要求严格；
3. 生产者消费侧解耦：调度线程（任务入队）与工作线程（任务执行）完全解耦，便于业务逻辑拆分；
4. 固定优先级任务：任务优先级划分明确（高 / 中 / 低），且优先级规则长期不变。

### 边界说明（非缺陷，是设计取舍）

1. **非抢占式优先级**：工作线程执行低优先级任务时，不会被高优先级新任务抢占，适合设备任务执行的原子性要求（电表采集 / 指令下发不可中断）；
2. **消费侧竞争**：高优先级队列任务量小时，多个工作线程会竞争同一队列，因队列锁粒度细，竞争开销可忽略；
3. **无全局任务监控**：去掉调度器后，无统一组件监控所有队列 / 任务 / 通道状态，需在**队列 / 通道层增加独立的监控接口**，实现分布式监控。

## 七、与原有 MeterChannel 的无缝集成点

1. **MeterChannel 内部无修改**：保留`channel_id_`/`state_`/`stop_flag_`/`current_meter_`原有设计，`current_meter_`仍由自身工作线程访问，无需加锁；
2. **仅扩展工作线程核心逻辑**：在 MeterChannel 的工作线程循环中，增加 **「按优先级探询队列→获取任务→执行→更新状态」** 的逻辑，其余代码完全复用；
3. **通道状态与探询联动**：MeterChannel 的`state_`（IDLE/BUSY/ERROR）与探询逻辑联动，仅当状态为 IDLE 时才会探询队列，BUSY/ERROR 时暂停探询，保证状态一致性。

该架构是**无中心调度器、消费侧自主探询**的经典生产者消费者模型，完美匹配你提出的「10 个消费者 + 3 个优先级生产者 + 无调度器」的核心需求，同时兼顾工业级设备的**实时性、稳定性、资源适配性**。
