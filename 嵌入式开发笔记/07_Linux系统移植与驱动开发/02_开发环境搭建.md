## 4.设置共享目录

1. 先关闭虚拟机

2. 设置并选择路径添加共享目录

3. 重新启动并登录`Ubuntu`系统

4. 执行

   ```bash
   vmware-hgfsclient #确定共享文件夹是否已设置
   ```

5. 执行如下命令后，可在"/mnt/hgfs/"下看到共享目录，即可通过共享目录传输文件

   ```bash
   sudo mkdir /mnt/hgfs
   sudo vmhgfs-fuse .host:/ /mnt/hgfs -o subtype=vmhgfs-fuse,allow_other
   
   
   #vmhgfs-fuse：VMware 提供的文件系统挂载工具，用于实现主机与虚拟机之间的文件共享
   #.host:/：表示 VMware 主机端共享的根目录（所有已配置的共享文件夹都在这里）
   #/mnt/hgfs：虚拟机中用于挂载共享目录的目标路径（挂载点）
   #-o subtype=vmhgfs-fuse,allow_other：挂载选项
   	- subtype=vmhgfs-fuse：指定文件系统子类型
   	- allow_other：允许非 root 用户访问挂载的共享目录（否则默认只有 root 可访问
   ```
6. 执行如下命令，修改 `fstab`配置文件，虚拟机启动后将自动挂载已设置的共享目录。

   ```bash
   sudo vim /etc/fstab
   ```

# 服务器配置

## 1.`TFTP`服务器

### 1.安装服务器

```shell
sudo apt-get install tftpd-hpa
#tftp-hpa（客户端）、tftpd-hpa（服务器）和 xinetd（配置文件）
```

### 2.配置服务器文件

```shell
# /etc/default/tftpd-hpa //配置文件的位置

TFTP_USERNAME="tftp"  #用户名
TFTP_DIRECTORY="/tftpboot" #工作路径，即要传输的文件所在目录
TFTP_ADDRESS="0.0.0.0:69"  #ip地址和端口号
TFTP_OPTIONS="-c -l -s"    #选项,类似于命令的选项，修改服务器的权限

#重启服务器，使配置生效
sudo service tftpd-hpa restart

#每次开启ubantu都要重启！！
```

## 2.NFS服务器

`nfs`（Network File System）即网络文件系统，其基于`UDP/IP`，使用nfs能够在不同计算机之间通过网络进行文件共享，能使使用者访问网络上其它计算机中的文件就像在访问自己的计算机一样。即不需要总频繁的编译再下载到开发板上运行，而可以直接在电脑上现编译好，开发板现执行。

### 1.安装服务器

```shell
sudo apt-get install nfs-kernel-server
```

### 2.修改配置文件

```shell
# Example for NFSv2 and NFSv3:
# /srv/homes       hostname1(rw,sync,no_subtree_check) hostname2(ro,sync,no_subtree_check)
#
/opt/4412/rootfs   *(rw,sync,no_subtree_check,no_root_squash)

#重启服务器，使配置生效
sudo service nfs-kernel-server restart

#每次开启ubantu都要重启！！
```

# 交叉编译工具链

## 1.交叉编译工具链内容

### 1.交叉编译工具

这些工具位于bin目录下：

- `arm-none-linux-gnueabi-gcc`

- `arm-none-linux-gnueabi-readelf`

- `arm-none-linux-gnueabi-gdb`等。s

### 2.常用命令

- **size**：列出ELF中能够直接在`cpu`上运行的段的每一段的大小，不包括elf头，调试信息，符号表等段。

  ```bash
  size /usr/lib64/libc.a
  ```

- **nm**：列出目标文件的符号表里的符号，如函数名，汇编标识符start，end等。

  ```bash
  nm /bin/ls
  ```

- **strip**：在生成elf文件时，系统会生成符号表，但我们用该命令删除elf文件的符号段且不会影响程序的执行，以此减少所占用空间，**这对嵌入式程序精简很重要**。

  ```bash
  strip File.out
  ```

- 通过file命令结果最后一句话来看文件是否被瘦过身。

  ```bash
  [root@linuxcool ~]# file /bin/ls /bin/ls
  ELF 64-bit LSB shared object, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 3.2.0, BuildID[sha1] =937708964f0f7e3673465d7749d6cf6a2601dea2, stripped, too many notes (256)
  ```

- **`objdump`**：“object files dump”的缩写，其功能是用于显示目标文件附加信息，显示elf文件信息。

  ```bash
  objdump [参数] 文件名
  	-d #反汇编，机器码->汇编语言 ，
  ```

- **`objcopy`**：转换文件格式，用于把elf文件转为bin格式

  ```shell
  objcopy [选项]... 输入文件 [输出文件]
  
  objcopy --gap-fill=0xff -O binary a.out a.bin
  #--gap-fill:用0xff去覆盖掉elf中除了数据段和代码段的其他段
  #-O :目标格式为binary
  ```

## 2.ELF文件格式

### 1.ELF介绍

ELF格式是Linux平台上应用最广泛的二进制工业标准之一。ELF格式的文件内包含了很多个段，不同的段存储了不同的信息；因为ELF格式的文件要通过Linux系统的加载和管理才能运行，所以除了最基本的代码段和数据段之外，其中还存储了很多其它的信息，如符号表、调试信息等。**运行在`linux`之上**，而不是裸机环境。
![image-20240803172533637](D:/MyNote/-/嵌入式开发笔记/figure/image-20240803172533637.png)

### 2.ELF相关命令

- `file` + 文件名

- `readelf`+文件名

  ```bash
  readelf [参数] [文件名]
  readelf -a libmy.so
  #查看elf文件详细信息
  ```

## 3.BIN文件格式

BIN，即二进制文件，一般是直接运行在CPU之上的可执行文件，**运行在没有操作系统的裸机之上**。文件内只包含了CPU能够直接识别和运行的指令和数据，不包含其它系统相关的信息。
